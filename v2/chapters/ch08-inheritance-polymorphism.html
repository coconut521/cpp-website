第8章 继承与多态

继承让类之间形成“is-a（是一种）”的层次，虚函数让同一调用在不同对象上产生不同行为。

学习目标

  • 用 class Derived : public Base 写 public 继承，说清 is-a 关系与 protected 成员的访问边界。
  • 按顺序说出一层继承对象的构造顺序（先基类后派生）与析构顺序（相反）。
  • 列出多态发生的三要素，解释按值传参发生切片（slicing）后多态失效。
  • 用 override 与 final（C++11）让编译器检查覆盖签名。
  • 解释纯虚函数与抽象类（不能实例化、用于接口设计），说清虚析构的必要性。
  • 预测“构造/析构函数中调用虚函数”的输出（不分发到派生类），识别名字隐藏与 using Base::f 的修复。

前置知识：第7章 类与对象（构造函数、析构函数、const 成员函数）。

1. public 继承与 protected 成员

class Dog : public Animal 读作“Dog 是一种 Animal”。public 继承表达 is-a 关系：任何需要 Animal 的地方（参数、容器、指针）都能放 Dog。基类的 public 成员在派生类中仍是 public，protected 仍是 protected。三种访问级别复习一遍：

成员属性类内部派生类内部外界（main 等）
public可访问可访问可访问
protected可访问可访问不可访问
private可访问不可访问不可访问
protected 对派生类开放、对外界不可见：派生类的成员函数可以访问它继承来的 protected 成员，外界代码不能。private 继承（class B : private A，可省略 private 时默认）表达“用 A 来实现 B”，本课程只要求认识语法，考试重点在 public 继承。

示例1：public 继承的基本语法与 protected 成员

知识点：继承语法入门必会
#include <iostream>
#include <string>

class Animal {
public:
    std::string name;
    void eat() const { std::cout << "吃东西\n"; }
protected:
    int age = 1;    // protected：派生类可访问，外界不可
};

class Dog : public Animal {   // public 继承：Dog is-a Animal
public:
    void bark() const { std::cout << name << " 汪汪叫\n"; }
    void grow() { ++age; std::cout << name << " 长到 " << age << " 岁\n"; }
};

int main() {
    Dog d;
    d.name = "旺财";
    d.eat();       // 继承自基类的公有成员
    d.bark();
    d.grow();
    // d.age = 5;   // ⛔ 编译错误：age 是 protected，外界不可访问
    return 0;
}
▶ 预期输出
吃东西
旺财 汪汪叫
旺财 长到 2 岁

逐行解释

  • 第12行：: public Animal 定义继承关系。Dog 对象内部包含一个完整的 Animal 子对象。
  • 第21行：eat 从基类原样继承而来，Dog 直接可用。
  • 第23行：grow 修改的是继承来的 protected 成员 age（1→2）。派生类成员函数有权访问。
  • 第24行：注释掉的这行若取消注释就是编译错误——外界访问 protected 成员被拒绝。

变体对比

把 age 改成 private：grow() 里的 ++age 也会变成编译错误——private 连“子女”都进不去，protected 比 private 只多开放“派生类内部”这一层。

⚠ 易错点

判断题“派生类可以访问基类的 private 成员”为假；能访问的是 public 和 protected。反过来，“外界可以访问 protected 成员”也是假。

2. 构造与析构顺序：先基类，后派生

派生类对象由“基类子对象 + 派生类自己的成员”拼成。构造时先基类、再成员、最后才执行派生类构造函数体；析构严格相反。若基类构造函数需要参数，派生类必须在初始化列表里显式调用它：Derived(int v) : Base(v) {}。

示例2：构造 1→2→3，析构 4→5→6（严格相反）

知识点：构造/析构顺序高频考点
#include <iostream>

class Base {
public:
    Base()  { std::cout << "1. Base 构造\n"; }
    ~Base() { std::cout << "6. Base 析构\n"; }
};

class Member {
public:
    Member()  { std::cout << "2. Member 构造\n"; }
    ~Member() { std::cout << "5. Member 析构\n"; }
};

class Derived : public Base {
public:
    Member m;   // 成员对象
    Derived()  { std::cout << "3. Derived 构造\n"; }
    ~Derived() { std::cout << "4. Derived 析构\n"; }
};

int main() {
    Derived d;
    std::cout << "---- d 的构造已完成 ----\n";
    return 0;
}
▶ 预期输出
1. Base 构造
2. Member 构造
3. Derived 构造
---- d 的构造已完成 ----
4. Derived 析构
5. Member 析构
6. Base 析构

逐行解释

  • 构造 1→2→3：先调用基类 Base 构造函数；然后构造成员 m（成员在进入派生类构造函数体之前构造好）；最后才执行 Derived() 函数体——函数体执行时，基类和成员已就绪。
  • 析构 4→5→6：d 在 main 结束时销毁，顺序与构造严格相反：先派生类析构函数体，再成员，最后基类。
  • 多层继承同理：Base → Mid → Derived，析构倒过来。

变体对比

基类构造带参数时必须在初始化列表里调用：Derived(int v) : Base(v), m() {}——漏写 Base(v) 且 Base 无默认构造时是编译错误。

⚠ 易错点

选择题最爱把“成员先于基类构造”当正确项。永远是基类最先构造，成员排在基类之后、派生类函数体之前；析构完全相反。

3. 虚函数与动态绑定：多态的核心

把基类成员函数标成 virtual，再通过基类指针或基类引用去调用，执行哪个版本就由对象的动态类型在运行时决定——这叫动态绑定（动态多态）。发生多态的三个要素缺一不可：① 函数是虚函数；② 通过指针或引用调用；③ 指针/引用实际指向派生类对象。

示例3：同一调用语句，不同对象不同行为

知识点：虚函数 / 动态绑定高频考点
#include <iostream>

class Shape {
public:
    virtual void draw() const { std::cout << "画一个 Shape\n"; }
    virtual ~Shape() {}          // 多态基类配虚析构（第 7 节细讲）
};

class Circle : public Shape {
public:
    void draw() const override { std::cout << "画一个圆形 ●\n"; }
};

class Square : public Shape {
public:
    void draw() const override { std::cout << "画一个方块 ■\n"; }
};

void paint(const Shape& s) { s.draw(); }   // 通过基类引用调用 → 动态绑定

int main() {
    Circle c;
    Square sq;
    Shape* p = &c;
    p->draw();        // 基类指针指向 Circle → 调 Circle::draw
    p = &sq;
    p->draw();        // 同一条语句，指向 Square → 调 Square::draw
    paint(c);         // 基类引用绑定 Circle → 调 Circle::draw
    return 0;
}
▶ 预期输出
画一个圆形 ●
画一个方块 ■
画一个圆形 ●

逐行解释

  • 第5行：virtual 把 draw 声明为虚函数，这是动态绑定的“开关”。派生类里重复写 virtual 可省略（写了也对）。
  • 第24行：Shape* p = &c; —— 指针的静态类型是 Shape*，但它指向的对象的动态类型是 Circle。
  • 第25、27行：同一条语句 p->draw() 执行了两次、打印了不同结果——因为 draw 是虚函数，运行时“看对象本身”选版本。这就是多态。
  • 第28行：通过基类引用 s.draw() 同样动态绑定；函数参数写成 const Shape& 是多态设计的标准写法。

变体对比

若直接用对象调用：c.draw(); —— 对象类型在编译期就完全确定，走的是静态绑定（结果同样是 Circle 版本，但机制不同）。只有“指针或引用 + 虚函数”才谈得上动态绑定。

⚠ 易错点

派生类里的 override 关键字是 C++11 的“保险丝”，本例先混个眼熟，下一节详解它。

❌ 没有 virtual（按静态类型调用）

// 片段：draw 不是虚函数
struct Shape {
    void draw() const {
        std::cout << "Shape\n"; }
};
struct Circle : Shape {
    void draw() const {
        std::cout << "Circle\n"; }
};

Shape* p = new Circle;
p->draw();   // 看"指针类型"
             // → Shape

输出：

Shape

✅ 有 virtual（按动态类型调用）

// 片段：draw 是虚函数
struct Shape {
    virtual void draw() const {
        std::cout << "Shape\n"; }
    virtual ~Shape() {}  // 配虚析构
};
struct Circle : Shape {
    void draw() const override {
        std::cout << "Circle\n"; }
};

Shape* p = new Circle;
p->draw();   // 看"对象类型"
             // → Circle

输出：

Circle
底层一句话：每个含虚函数的类有一张“虚函数表”，对象里存一个指向它的指针；调用虚函数时按对象里的指针查表——所以“看对象本身”，而不是“看指针的类型”。虚函数有少量运行期开销。

4. 对象切片：按值传递丢失派生部分

用派生类对象去初始化或赋值一个基类对象（注意：是对象，不是指针/引用）时，只有基类子对象被复制，派生类部分被丢弃——这就是对象切片（slicing）。切片出来的对象虚表也是基类的，多态彻底失效。这是“同一份代码，为什么行为不对”的经典考题。

示例4：按值传参切片，按引用传参多态

知识点：对象切片高频考点经典陷阱
#include <iostream>

class Animal {
public:
    virtual void speak() const { std::cout << "Animal 声音\n"; }
    virtual ~Animal() {}
};

class Cat : public Animal {
public:
    void speak() const override { std::cout << "喵~\n"; }
};

void byValue(Animal a)      { a.speak(); }   // 按值：发生切片
void byRef(const Animal& a) { a.speak(); }   // 按引用：多态保留

int main() {
    Cat cat;
    Animal& r = cat;       // 引用：cat 完整无缺
    Animal  v = cat;       // ⚠ 切片：v 只拷贝了 Animal 子对象

    byValue(cat);          // 喵丢失 → Animal 声音
    byRef(cat);            // 多态 → 喵~
    r.speak();             // 喵~
    v.speak();             // Animal 声音（v 已是纯 Animal）
    return 0;
}
▶ 预期输出
Animal 声音
喵~
喵~
Animal 声音

逐行解释

  • 第19行：Animal& r = cat; 只是给 cat 起别名，cat 本身不变，r.speak() 动态绑定到 Cat。
  • 第20行：Animal v = cat; 触发 Animal 的拷贝构造——只复制 Animal 子对象，Cat 的部分被丢弃。v 已是纯 Animal 对象。
  • 第22行：byValue 的形参是 Animal a，传入时发生一次与第 20 行完全相同的切片——函数里无论做什么都不再多态。
  • 第23行：byRef 的形参是 const Animal&，引用直接绑到 cat 上，多态完好。

⚠ 易错点

std::vector<Animal> 里存 Cat 也会切片（容器元素就是按值存的）。要多态请存指针：std::vector<std::unique_ptr<Animal>>（第 9 章详述智能指针）。

函数参数永远写 const Shape& 而不是 Shape：既省一次拷贝，又保住多态。

5. override 与 final（C++11）

override 明确告诉编译器“我要覆盖基类虚函数”：签名对不上就编译报错，把运行期才暴露的 bug 消灭在编译期。final 反过来：禁止派生类再覆盖这个虚函数（用在类上则禁止再继承）。这两个关键字没有运行期开销，现代 C++ 中派生类覆盖虚函数必须写 override。

示例5：少写一个 const，“覆盖”静默变成新函数（经典 bug）

知识点：override高频考点经典陷阱
#include <iostream>

class Base {
public:
    virtual void show() const { std::cout << "Base::show\n"; }
    virtual ~Base() {}
};

class Derived : public Base {
public:
    void show() { std::cout << "Derived::show\n"; }
    // ⚠ 少写了 const：签名与 Base::show() const 不同，
    //   这不是覆盖，而是定义了一个新函数并"隐藏"了基类版本！
    // 若写成 void show() override { ... } —— 编译错误，bug 当场暴露
};

int main() {
    Derived d;
    Base* p = &d;
    p->show();   // 想多态，但 Derived 没覆盖 → 调的仍是 Base::show
    d.show();    // 直接调用：名字查找选中的是 Derived 的新函数
    return 0;
}
▶ 预期输出
Base::show
Derived::show

逐行解释

  • 第11行：虚函数的签名包括参数列表和 const 修饰。show() 与 show() const 是两个不同的函数，前者不能覆盖后者。
  • 第20行：p->show() 走动态绑定，但 Derived 根本没有覆盖 show() const，虚表里还是 Base 的版本——程序员以为的多态静默失效。
  • 第21行：d.show() 直接按对象类型做名字查找，找到 Derived 的新函数（顺带把基类的 show() const 隐藏了）。
  • 给第 11 行加上 override：编译器立即报错“标记了 override 但没有匹配的虚函数可覆盖”，bug 在编译期现形。这就是 override 的全部价值：防拼写错、防签名不匹配。

变体对比

同类的坑还有：基类是 show(int)，派生类写成 show(double)；或基类函数名拼错。override 能在编译期拦住这类问题。

⚠ 易错点

override 不是虚函数的“开关”（开关是基类的 virtual），它是编译期检查标记。判断题“加了 override 才是虚函数”为假。

示例6：final——禁止再覆盖、禁止再继承

知识点：finalC++11
#include <iostream>

class Base {
public:
    virtual void log() const { std::cout << "Base::log\n"; }
    virtual ~Base() {}
};

class Mid : public Base {
public:
    void log() const final { std::cout << "Mid::log\n"; }
    // ↑ final：到此为止，任何派生类不得再覆盖 log
};

// class Bad : public Mid {
// public:
//     void log() const override { }   // ⛔ 编译错误：log 已被 final 锁定
// };

int main() {
    Mid m;
    Base* p = &m;
    p->log();        // 覆盖链仍然有效：调 Mid::log
    return 0;
}
▶ 预期输出
Mid::log

逐行解释

  • 第11行：final 加在被覆盖的虚函数上：Mid 覆盖了 Base::log，同时禁止派生类再覆盖。取消注释 Bad 即得编译错误。
  • 第23行：Mid 对 log 的覆盖本身有效，动态绑定正常发生。

变体对比

final 也可以用在类名上：class Mid final : public Base { ... }; —— 整个类禁止被继承，安全性检查也更友好。设计“到此为止、不许扩展”的类时使用。

⚠ 易错点

final 不是“终结这个函数存在”，而是“终结覆盖链/继承链”。final 修饰虚函数时该函数仍可被正常调用与动态绑定。

6. 纯虚函数与抽象类：接口设计

virtual double area() const = 0; 是纯虚函数：只声明“我有什么能力”，不给实现。含纯虚函数的类叫抽象类：不能创建对象，只能被继承，是 C++ 表达“接口”的方式。派生类必须实现全部纯虚函数，否则它自己也是抽象类。

示例7：抽象类 Shape 作为接口，派生类各自实现

知识点：纯虚函数 / 抽象类高频考点
#include <iostream>

class Shape {                          // 抽象类：含纯虚函数
public:
    virtual double area() const = 0;   // 纯虚函数：= 0 表示"无实现，必须覆盖"
    virtual void   describe() const = 0;
    virtual ~Shape() {}
};

class Circle : public Shape {
public:
    explicit Circle(double r) : radius(r) {}
    double area() const override { return 3.14159 * radius * radius; }
    void   describe() const override {
        std::cout << "圆形，面积 " << area() << "\n";
    }
private:
    double radius;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w(w), h(h) {}
    double area() const override { return w * h; }
    void   describe() const override {
        std::cout << "矩形，面积 " << area() << "\n";
    }
private:
    double w, h;
};

int main() {
    // Shape s;         // ⛔ 编译错误：抽象类不能实例化
    Circle c(2.0);
    Rect r(3.0, 4.0);
    Shape* shapes[2] = { &c, &r };   // 基类指针数组：统一管理不同图形
    for (Shape* s : shapes) s->describe();   // 同一条语句，两种行为
    return 0;
}
▶ 预期输出
圆形，面积 12.5664
矩形，面积 12

逐行解释

  • 第5~6行：= 0 是纯虚函数的标志。Shape 只规定“图形必须能算面积、能 describe”，自己不实现——所以禁止实例化。
  • 第33行：抽象类唯一合法的用法就是当基类。注释掉的那行取消注释即编译错误。
  • 第37行：范围 for 遍历基类指针数组，s->describe() 一条语句分别调出 Circle、Rect 的版本；describe 内部再调 area()，同样动态绑定到各自的实现。新增图形时只需再加一个派生类，这段循环不用改。
  • 输出：3.14159×2×2 = 12.56636，cout 默认 6 位有效数字显示 12.5664；3×4 = 12.0 显示为 12。

⚠ 易错点

派生类只要漏实现任意一个纯虚函数，它自己也成了抽象类——此时 Circle c(2.0); 报编译错误“不能实例化抽象类”。另外，抽象类可以有构造函数（供派生类调用）、可以有数据成员，“抽象 = 什么都没有”是误解。

7. 虚析构函数

多态场景里，对象常用 new 创建、用基类指针持有，最后 delete 这个基类指针。此时 delete 调用哪个析构函数，取决于析构函数是不是 virtual——不是，就是未定义行为。

示例8：基类析构不是 virtual 时 delete 基类指针（UB 示范）

未定义行为示范高频考点
#include <iostream>

class Shape {
public:
    Shape()  { std::cout << "Shape 构造\n"; }
    ~Shape() { std::cout << "Shape 析构\n"; }   // ⚠ 不是 virtual
};

class Circle : public Shape {
public:
    Circle()  { std::cout << "  Circle 构造\n"; }
    ~Circle() { std::cout << "  Circle 析构\n"; }
};

int main() {
    Shape* p = new Circle();   // 基类指针指向派生类对象
    delete p;                  // ⛔ 静态类型 Shape 的析构不是 virtual
    return 0;
}

⚠ 为什么没有“预期输出”？

通过基类指针 delete 一个派生类对象，而基类析构函数不是 virtual——这是未定义行为（标准 §expr.delete：静态类型与动态类型不符且基类析构非虚时，结果未定义）。常见症状是只执行 Shape::~Shape（派生类析构被跳过，若派生类持有资源即泄漏），但标准允许任何结果。因此本例不给出预期输出；凡“给出非虚析构 + 基类指针 delete 的确定输出”的考题本身就是错题。

修复：把 ~Shape() 改成 virtual ~Shape() = default;。经验法则：只要一个类会被继承（作为多态基类使用），它的析构函数就声明为 virtual。

变体对比：修复后（虚析构，可安全 delete）

#include <iostream>

class Shape {
public:
    virtual ~Shape() = default;   // 虚析构
};

class Circle : public Shape {
public:
    ~Circle() { std::cout << "Circle 析构\n"; }
};

int main() {
    Shape* p = new Circle();
    delete p;      // 先 ~Circle 再 ~Shape，完整析构
    return 0;
}

预期输出：

Circle 析构

析构从实际类型出发、自上而下走完整条链：先派生类析构函数体，再基类——与栈上对象（示例2）的方向一致。

记法：构造“自底向上搭积木”（基类 → 成员 → 派生类），析构“自顶向下拆积木”。虚析构保证 delete 基类指针 时从正确的积木开始拆。

8. 构造/析构函数中调用虚函数：不分发（经典考题）

构造 Base 部分时，对象的“已构造完成的部分”还只是 Base（Derived 部分尚未出生）；析构到 Base 时，Derived 部分“已经没了”。因此标准规定：在构造函数和析构函数中调用虚函数，调用的是“当前正在构造/析构的类”自己的版本，不会动态分发到派生类。

示例9：构造函数中调用 init() 解析到哪个版本

知识点：构造/析构与虚函数高频考点经典陷阱
#include <iostream>

class Base {
public:
    Base() { init(); }                              // 构造函数中调用虚函数
    virtual void init() { std::cout << "Base::init\n"; }
    virtual ~Base() {}
};

class Derived : public Base {
public:
    void init() override { std::cout << "Derived::init\n"; }
};

int main() {
    Derived d;    // 构造期间：Base::Base() 里调用了 init()
    d.init();     // 对象构造完成后：正常动态绑定
    return 0;
}
▶ 预期输出
Base::init
Derived::init

逐行解释

  • 第5行：构造 d 时先执行 Base()。此刻 Derived 部分还没构造，对象的动态类型“暂记为 Base”，虚函数机制只能看到 Base 的虚表——init() 解析到 Base::init，不会分发到 Derived 的版本。
  • 第17行：整个对象构造完成后，动态类型才变成 Derived；这时再调 init()（经对象调用，静态类型即 Derived）走到 Derived::init。
  • 析构方向同理：~Derived 执行完、进入 ~Base 后，对象“退化”回 Base——此时调用虚函数得到的是 Base 的版本。构造越走越“具体”，析构越走越“抽象”，虚分发只能看见“当前这一层”。
  • 工程启示：别指望基类构造函数能调用到派生类的初始化逻辑；需要“两段式初始化”时显式提供并调用初始化函数。

变体对比

若把 init 改成纯虚函数（Base 不给实现），Base() 里调用它会链接失败/未定义——因为此刻“Base 的版本”根本不存在。这也反证了上面的规则。

⚠ 易错点

判断题“构造函数中调用虚函数会分发到派生类 override 版本”为假。这不是 UB，是标准明文规定的行为——考试可以考它的确定输出。

9. 名字隐藏与 using Base::f

派生类里定义了与基类同名的函数（无论参数是否相同、无论虚不虚），基类的整个同名重载集都被隐藏——这不是重载，是名字隐藏（name hiding）：名字查找先在派生类作用域完成，找到了就不再上溯。要恢复基类的重载集，在派生类里写 using Base::f;。

示例10：一个 f(int) 隐藏了基类的全部 f

知识点：名字隐藏高频考点
#include <iostream>

class Base {
public:
    void f()      { std::cout << "Base::f()\n"; }
    void f(int x) { std::cout << "Base::f(int)=" << x << "\n"; }
};

class Derived : public Base {
public:
    void f() { std::cout << "Derived::f()\n"; }  // 隐藏了 Base::f() 和 Base::f(int)
    // using Base::f;  ← 取消注释可恢复基类的全部重载
};

int main() {
    Derived d;
    d.f();       // Derived::f()
    // d.f(3);   // ⛔ 编译错误：Base::f(int) 被名字隐藏，重载集没有带进来
    Base& b = d;
    b.f();       // 非虚函数：按静态类型调用 → Base::f()
    b.f(3);      // Base::f(int)=3
    return 0;
}
▶ 预期输出
Derived::f()
Base::f()
Base::f(int)=3

逐行解释

  • 第11行：派生类的 f() 与基类的 f(int) 参数不同，不构成重载——按名字查找：先找到 Derived 作用域里的 f，查找停止，基类的所有 f 一律不可见。
  • 第18行：d.f(3) 因此是编译错误：候选只有 Derived::f()，不接受 int 实参。
  • 第19~21行：f 不是虚函数，经基类引用调用按静态类型 Base 查找 → Base 的两个重载都正常可用。
  • 修复：在 Derived 里加 using Base::f;，把基类重载集引入派生类作用域，d.f(3) 立刻合法。

变体对比

名字隐藏与虚函数互不冲突：若基类 virtual void f()、派生类 void f(int)，前者被隐藏（虚表还在，经基类指针调用仍是多态），后者是普通新函数。分两件事记忆：虚不虚看基类声明，见不见得到看名字查找。

⚠ 易错点

“派生类的 f(int) 和基类的 f() 构成重载”是假命题——跨类作用域没有重载，只有隐藏。重载只发生在同一个作用域里。

10. 多继承、菱形继承与虚继承（点到为止）

语法上一个类可以继承多个基类：class D : public B, public C。多继承容易带来二义性与菱形结构，工程上建议慎用（优先单继承 + 组合），考试一般只考概念。菱形继承：B、C 都继承 A，D 又继承 B、C——D 中会有两份 A 子对象，访问 A 的成员产生二义性。让 B、C 用虚继承（virtual public A），则 D 中只保留一份 A。

示例11：菱形继承 + 虚继承，A 只有一份

知识点：菱形继承 / 虚继承了解即可
#include <iostream>

class A { public: int x = 1; };

class B : virtual public A { };   // 虚继承：声明"我愿意与别人共享这份 A"
class C : virtual public A { };   // 同上
class D : public B, public C { }; // 菱形：D 中只有一份 A

int main() {
    D d;
    d.x = 42;                      // 若不用虚继承：编译错误（二义性）
    A* p1 = static_cast<B*>(&d);   // 经 B 看到的 A 子对象
    A* p2 = static_cast<C*>(&d);   // 经 C 看到的 A 子对象
    std::cout << d.x << "\n";
    std::cout << (p1 == p2 ? "同一个 A" : "两个不同的 A") << "\n";
    return 0;
}
▶ 预期输出
42
同一个 A

逐行解释

  • 第5~6行：virtual public A 是虚继承的写法（virtual 与 public 顺序可换）。它不代表虚函数，纯粹是继承方式的关键字——一词两用，注意区分。
  • 第11行：虚继承后 D 只含一份 A，d.x 没有二义性。若去掉两个 virtual，此行直接编译错误：“x 是二义的”。
  • 第12~13行：两条路径向上取 A 子对象，指针相等（p1 == p2 为真）说明确实只有一份。不用虚继承时是两个不同的 A，两行会打印“两个不同的 A”。

变体对比

虚继承的代价：对象里要存额外的“虚基类偏移”信息，访问虚基类成员也多一次间接。标准库 iostream 体系就是最著名的虚继承案例（istream、virtual public ios）。

⚠ 易错点

判断题“菱形继承必然导致编译错误”为假——不虚继承也能编译，只是访问公共基类成员（或把 D* 转成 A*）时二义报错。考概念时答“两份基类子对象、需虚继承合并”即可。

12. 常见错误

1. 忘写 virtual，“多态”静默失效——基类函数没标 virtual，派生类同签名函数只是隐藏；指针调用永远走基类版本。修复：基类标 virtual，派生类加 override 让编译器验证。
2. 按值传参 / 按值存储导致切片——void f(Shape s)、vector<Shape> 都会斩掉派生部分。修复：参数用 const Shape&，容器存 unique_ptr<Shape>。
3. 覆盖签名不匹配——少写 const、参数类型不同、函数名拼错，都让“覆盖”变成新函数。修复：一律写 override，签名错直接编译报错。
4. 基类析构非虚 + 基类指针 delete 派生类对象——未定义行为（示例 8）：标准不保证派生类析构执行，常见症状是资源泄漏。修复：多态基类的析构函数声明为 virtual。这不是“会输出什么”的问题，考试不考它的输出，只考“这是 UB，必须虚析构”。
5. 名字隐藏误伤基类重载集——派生类定义一个同名函数，基类同名函数全部不可见。修复：派生类内 using Base::f;。
6. 在构造/析构函数中调用虚函数期待派生类版本——调到的是“当前正在构造/析构的类”的版本（示例 9）。这是确定行为，不是 UB，但常被当成 bug 报告；要两段式初始化请显式调用 init 函数。

更多同类错误见 编译错误博物馆（如“不能实例化抽象类”“成员初始化顺序”），以及 考试易错点 中的“继承与多态”专题。

本章小结

public 继承是 is-a；多态 = 虚函数 + 基类指针/引用；凡对象要经基类指针 delete，基类析构就必须是 virtual。
  • 构造顺序：基类 → 成员 → 派生类函数体；析构严格相反。
  • 多态三要素：虚函数、经指针/引用调用、实际对象是派生类。按值传参必切片。
  • override 防签名写错，final 封锁覆盖与继承；抽象类（含纯虚函数）不能实例化，是接口。
  • 虚析构缺失时 delete 基类指针 是 UB；非虚析构不是考点输出，是必修修的 bug。
  • 构造/析构中调用虚函数只调“当前类”版本，不分发；名字隐藏按名字整体生效，using Base::f; 恢复重载集。
  • 多继承语法存在但要慎用；菱形继承用虚继承合并公共基类（点到为止）。
