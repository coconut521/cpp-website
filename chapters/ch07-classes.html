第7章 类与对象

类把数据和操作这些数据的函数封装成自定义类型。构造、析构、拷贝构造是本章重点，也是理解继承与智能指针的基础。

学习目标

  • 说出 class 与 struct 的唯一默认区别（默认 private / 默认 public）。
  • 用 public / private / protected 划分接口与实现，写 const 成员函数。
  • 写成员初始化列表，说清 const 成员、引用成员为什么只能用它；记住成员初始化顺序 = 声明顺序。
  • 说出构造、析构、拷贝构造的触发时机，以及析构顺序与构造相反。
  • 区分浅拷贝与深拷贝，为带指针成员的类写全 Rule of Three（三大件）。
  • 使用 static 成员（类外定义）与 =default / =delete（C++11）。

前置知识：第1章 变量与基本类型。示例 8、9 会用到 new/delete（第 5 章的主题）。

1. 从 struct 到 class：封装的起点

在 C++ 里 class 和 struct 几乎是同一个东西：都能有成员函数、构造函数、访问说明符。唯一默认区别：class 的成员默认是 private，struct 的成员默认是 public。

❌ class：默认 private

class Point {
    int x;   // 默认 private
    int y;
};

Point p;
p.x = 1;   // ⛔ 编译错误：
           // x 是私有的

✅ struct：默认 public

struct Point {
    int x;   // 默认 public
    int y;
};

Point p;
p.x = 1;   // ✅ 可以：
           // struct 默认公开
书写惯例（并非语法强制）：只装数据的“聚合体”用 struct（如上一章示例 4 的 Part），带有行为、需要保护数据的类型用 class。考试判断题“struct 不能有成员函数”为假。

2. 访问说明符、成员函数与 this

访问说明符决定“谁能碰这些成员”，从说明符那一行起生效，直到下一个说明符或类结束。

说明符类外可访问派生类可访问（第 8 章）典型用途
public是是对外接口：成员函数
private否否数据成员、内部实现细节
protected否是继承体系中留给子类用的成员

const 成员函数：参数列表后加 const（如 void f() const），承诺“不修改任何数据成员”。Getter 类函数应该一律加 const；要修改成员的函数不能加。

this 指针：每个成员函数都带一个隐藏参数 this——“当前对象的地址”（类型 类名*，const 成员函数里是 const 类名*）。s.introduce() 实质上是 introduce(&s)。平时不用写它，但在“返回自身”“判断参数是不是自己”时必须显式使用（见示例 9）。

示例1：第一个类 —— 私有数据 + 公开接口

入门必会
#include <iostream>
#include <string>

class Student {
public:                              // 公开：类外可以调用
    void introduce() const {         // const 成员函数：只读
        std::cout << "我是" << name_ << "，学号 " << id_ << "\n";
    }
    void rename(std::string new_name) {   // 要写成员 → 不能是 const
        name_ = new_name;
    }
private:                             // 私有：类外访问被编译器拒绝
    std::string name_ = "未命名";    // 类内默认初始化（C++11，第 5 节细讲）
    int id_ = 0;
};

int main() {
    Student s;
    s.rename("李华");
    s.introduce();
    // std::cout << s.name_;        // ⛔ 编译错误：name_ 是私有的
    return 0;
}
▶ 预期输出
我是李华，学号 0

逐行解释

  • 第5~11行：public 区是对外接口。introduce 只读成员，加 const；rename 要写 name_，不能加。
  • 第12~15行：private 区把数据藏起来——外界只能通过公开函数间接读写，这就是封装：数据何时合法、如何变化，由类自己把关。
  • 第21行：取消注释会得到类似 error: 'name_' is a private member of 'Student' 的编译错误——封装是编译期强制的。
  • 数据成员命名带下划线后缀（name_）是常见风格，用来与参数名区分。

变体对比

把 class 换成 struct 且不写任何访问说明符：第 21 行就不再报错（成员默认 public）。可见“能否访问”由默认权限 + 说明符共同决定。

⚠ 易错点

类定义结束时必须带分号：};。漏掉分号时，报错往往出现在下一行，非常迷惑人。

3. 构造函数与成员初始化列表

构造函数与类同名、没有返回类型，在对象创建时自动执行，负责把每个成员置成合法状态。不写构造函数时，编译器生成一个什么都不做的隐式默认构造；但只要手写了任意一个构造函数，隐式默认构造就不再生成（除非用 =default 要回，见示例 12）。

示例2：默认构造、带参构造与成员初始化列表

知识点：构造函数高频考点
#include <iostream>
#include <string>

class Cat {
public:
    Cat() : name_("无名猫"), age_(0) {   // 默认构造函数：无参
        std::cout << "默认构造：" << name_ << "\n";
    }
    Cat(std::string name, int age)       // 带参构造
        : name_(name), age_(age) {        // ⭐ 成员初始化列表
        std::cout << "带参构造：" << name_ << "\n";
    }
private:
    std::string name_;
    int age_;
};

int main() {
    Cat a;              // 调用默认构造
    Cat b("咪咪", 2);   // 调用带参构造
    return 0;
}
▶ 预期输出
默认构造：无名猫
带参构造：咪咪

逐行解释

  • 第6行：Cat() 无参，叫默认构造函数。Cat a; 就调用它。
  • 第9~12行：冒号后是成员初始化列表：name_(name) 表示“用参数 name 直接初始化成员 name_”。每个成员只在列表中出现一次，用逗号分隔。
  • 第19~20行：两个对象分别走两条构造路径，输出两行。

变体对比

也可以给参数设默认值，用一个函数兼任两种构造：Cat(std::string name = "无名猫", int age = 0)——此时不能再写无参版本（调用会有歧义）。两种风格考试都认可。

⚠ 易错点

构造函数没有返回类型——写 void Cat() 是编译错误（那就不是构造函数了）。它与类同名是识别标志。

❌ 函数体内赋值

class A {
public:
    A(int v) {   // 成员先被“默认
                 // 初始化”，再赋值
        x = v;   // 对 int 只是浪费；
                 // 对 const/引用成员
    }            // 直接编译错误
private:
    int x;
};

✅ 成员初始化列表（推荐）

class A {
public:
    A(int v) : x(v) {
        // ✅ 出生即初始化，
        // 不经过“先默认
        // 构造再赋值”
    }
private:
    int x;
};

示例3：const 成员与引用成员 —— 只能初始化，不能赋值

编译错误示范高频考点
#include <iostream>

class Fixed {
public:
    Fixed(int v) {   // ⛔ 编译错误：const/引用成员没被初始化
        c = v;       // ⛔ 这一句是“赋值”，const 不允许被赋值
    }
private:
    const int c;     // const 成员：只能初始化一次
    int& r;          // 引用成员：出生必须绑定到别人
};

int main() {
    Fixed f(7);
    return 0;
}

/* g++ 报错大意（措辞随版本不同）：
   const 成员 c 没有初始化；
   引用成员 r 不能默认初始化 */

逐行解释

  • 第6行：函数体里的 c = v; 是赋值。但 const 成员和引用成员根本没有“先默认出生、再赋值”的机会——引用必须一出生就绑定对象，const 必须一出生就有值。
  • 正确写法是初始化列表：Fixed(int& v) : c(v), r(v) {}——const 成员和引用成员只能出现在初始化列表中，这是列表与函数体赋值的本质区别。

⚠ 易错点

引用成员绑定构造函数的按值参数会造成悬空：构造一结束参数就消亡。要绑定就传 int&（调用者的变量），并确保其生命周期长于对象。

4. 成员初始化顺序 = 声明顺序（经典考题）

不管初始化列表把谁写在前面，成员永远按它们在类里的声明顺序依次初始化。原因是：析构要按相反顺序进行，编译器必须固定一套与书写顺序无关的规则。

示例4：列表先写 b_，实际先构造 a_

知识点：成员初始化顺序高频考点
#include <iostream>

struct Part {
    explicit Part(const char* name) : name_(name) {
        std::cout << "构造 " << name_ << "\n";
    }
    const char* name_;
};

class Machine {
public:
    Machine() : b_("B 部件"), a_("A 部件") {}   // 列表里先写 b_
    Part a_;   // 但 a_ 声明在前 → 先构造 a_
    Part b_;
};

int main() {
    Machine m;
    return 0;
}
▶ 预期输出
构造 A 部件
构造 B 部件

逐行解释

  • 第12行：初始化列表的书写顺序是 b_ 在前——但它只决定“谁用什么初值”，不决定执行顺序。
  • 第13~14行：声明顺序 a_ 在前，所以先构造 a_（打印 A 部件），再构造 b_（打印 B 部件）。
  • 这也是考试的标准考法：“初始化列表的执行顺序由什么决定？”——答：成员的声明顺序。

变体对比

把成员声明换成 Part b_; Part a_;（列表不动），输出就会变成先 B 后 A——顺序确实跟着声明走。保险起见，初始化列表的书写顺序尽量与声明顺序一致。

⚠ 依赖顺序的写法是 UB

Bad(int v) : b_(v), a_(b_) {}（成员声明为 int a_; int b_;）：本意“用 b_ 初始化 a_”，但 a_ 按声明顺序先初始化，此时 b_ 还没被初始化——读未初始化成员是未定义行为。开启 -Wall -Werror=reorder 时 g++ 会警告“初始化顺序将与声明顺序不符”。不要让一个成员的初值依赖列表中排在它后面的成员。

5. 委托构造与类内默认成员初始化（C++11）

示例5：一个构造函数调用另一个构造函数

知识点：委托构造C++11
#include <iostream>

class Point {
public:
    Point() : Point(0, 0) { }              // ⭐ 委托构造（C++11）
    Point(int x, int y) : x_(x), y_(y) {   // 主构造函数
        std::cout << "主构造 (" << x_ << ", " << y_ << ")\n";
    }
    int x_ = 1;   // 类内默认成员初始化（C++11）
    int y_ = 1;
};

int main() {
    Point p1;            // 委托给 Point(0, 0)
    Point p2(3, 4);
    std::cout << p1.x_ << " " << p1.y_ << "\n";
    std::cout << p2.x_ << " " << p2.y_ << "\n";
    return 0;
}
▶ 预期输出
主构造 (0, 0)
主构造 (3, 4)
0 0
3 4

逐行解释

  • 第5行：Point() : Point(0, 0) {} 在初始化列表的位置调用同类的另一个构造函数，把公共逻辑集中到主构造，避免复制粘贴。
  • 第9~10行：类内默认成员初始化：声明成员时直接给初值。当某成员没被初始化列表覆盖时，就用这里的值兜底。
  • 第16~17行：p1、p2 的 x_、y_ 都被主构造的列表覆盖，所以分别是 0 0 和 3 4。

⚠ 易错点

委托构造的初始化列表里不能再写其他成员：Point() : x_(0), Point(0, 0) {} 是编译错误——委托和成员初始化只能二选一。

6. 析构函数与析构顺序

析构函数写成 ~类名()：无参数、无返回值、最多一个。对象消亡时自动执行，负责收尾（释放堆内存、关文件……）。调用时机：

  • 栈上的局部对象：离开作用域时（大括号结束、函数返回）。
  • new 出来的对象：执行 delete 时。
  • 临时对象：所在表达式结束时。
  • 全局 / static 对象：main 结束之后。

顺序永远与构造相反——“后出生的先退场”，和栈的行为一致。成员的析构在析构函数体之后自动进行（std::string 成员会自己释放内存——这就是 RAII 思想，第 9 章展开）。

示例6：析构顺序演示 —— 与构造相反

知识点：析构函数高频考点
#include <iostream>
#include <string>

class Logger {
public:
    Logger(std::string name) : name_(name) {
        std::cout << "构造 " << name_ << "\n";
    }
    ~Logger() {                              // 析构函数：~类名，无参无返回
        std::cout << "析构 " << name_ << "\n";
    }
private:
    std::string name_;
};

int main() {
    Logger a("a");
    {
        Logger b("b");
        Logger c("c");
    }                    // 离开作用域：c、b 依次析构
    Logger d("d");
    return 0;
}                        // main 结束：d、a 依次析构
▶ 预期输出
构造 a
构造 b
构造 c
析构 c
析构 b
构造 d
析构 d
析构 a

逐行解释

  • 第17行：a 出生。
  • 第19~20行：进入内层大括号，b、c 依次出生。
  • 第21行：大括号一结束，括号内的对象按构造的相反顺序析构：先 c 后 b。a、d 不受影响。
  • 第24行：main 结束，剩下的局部对象逆序析构：d（最后构造的先走），然后 a。

记忆法

把每个大括号想成一个“盘子”：进括号时往盘里叠对象，出括号时从顶上一个个拿走——后放上去的先被拿走。

⚠ 易错点

析构函数不能带参数、不能重载、没有返回值；一个类只能有一个析构函数。写 void ~Logger() 或 ~Logger(int x) 都是编译错误。

7. 拷贝构造

拷贝构造函数的签名固定为 类名(const 类名& other)。它在三种情况下被调用：

  • 初始化：用已有对象创建新对象（T b = a;、T b(a);）。
  • 按值传参：实参复制给形参。
  • 按值返回：函数返回对象时复制一份（编译器常可优化掉，见“标准差异”）。

不写拷贝构造时，编译器自动生成一个“逐成员复制”的版本——对指针成员来说，复制的只是地址，这就是下一节浅拷贝问题的根源。

示例7：拷贝构造发生了几次

知识点：拷贝构造触发时机高频考点
#include <iostream>
#include <string>

class Box {
public:
    explicit Box(std::string tag) : tag_(tag) {
        std::cout << "构造 " << tag_ << "\n";
    }
    Box(const Box& other) : tag_(other.tag_) {   // 拷贝构造：参数是自身 const 引用
        std::cout << "拷贝 -> " << tag_ << "\n";
    }
    std::string tag() const { return tag_; }
private:
    std::string tag_;
};

void take(Box b) {                   // 按值传参：触发一次拷贝构造
    std::cout << "take 收到 " << b.tag() << "\n";
}

int main() {
    Box b1("b1");
    Box b2 = b1;     // 用已有对象初始化新对象：拷贝构造
    take(b1);        // 按值传参：拷贝构造
    return 0;
}
▶ 预期输出
构造 b1
拷贝 -> b1
拷贝 -> b1
take 收到 b1

逐行解释

  • 第22行：普通构造，输出“构造 b1”。
  • 第23行：Box b2 = b1; 用已有对象初始化新对象——调用拷贝构造（即使有 = 号，也不是赋值）。
  • 第24行：按值传参，形参 b 由 b1 拷贝构造。
  • 两次拷贝都来自左值 b1，编译器不允许消除，输出确定。

变体对比

Box b3 = Box("b3"); 是“从临时对象初始化”——C++17 起强制消除拷贝，只构造一次（见“标准差异”一节）。所以判断“会不会拷贝”要先分清来源是左值还是临时对象。

⚠ 易错点

Box b2 = b1; 的 = 是初始化不是赋值，走拷贝构造；而 b2 = b1;（b2 已存在）走的是拷贝赋值运算符。两者是不同的函数，考题常混着考。

8. 浅拷贝与深拷贝

示例8：默认拷贝 + 指针成员 = 双重释放（UB）

未定义行为示范高频考点
#include <iostream>

class IntBag {
public:
    explicit IntBag(int v) : data_(new int(v)) {}  // 在堆上分配一块 int
    ~IntBag() { delete data_; }                    // 每个对象负责释放自己的堆内存
    int* data_;    // 为演示，暂时公开
};

int main() {
    IntBag a(42);
    IntBag b = a;   // 编译器生成的拷贝构造：逐成员复制 → 只复制了指针本身！
    std::cout << *b.data_ << "\n";
    return 0;
}   // ⛔ a、b 析构时先后 delete 同一块内存：双重释放

逐行解释

  • 第5行：构造函数用 new 在堆上分配 int，对象只保存它的地址。
  • 第12行：编译器生成的拷贝构造把 data_ 逐字节复制——两个对象的指针指向同一块堆内存。这就是浅拷贝：复制了地址，没复制内容。
  • 第15行：main 结束，a、b 各自析构、各自 delete——同一块内存被释放两次。

⚠ 为什么没有“预期输出”？

对同一块内存 delete 两次是未定义行为：堆结构可能被破坏，程序可能崩溃（glibc 下常见 free(): double free detected），也可能毫无征兆地错下去。标准不规定结果，考试不会也不应考它的“输出”。修复方法见示例 9 的深拷贝：新对象在堆上另开一块内存、复制内容而不是地址。

示例9：Rule of Three —— 三大件的深拷贝

知识点：拷贝赋值 / Rule of Three高频考点
#include <iostream>

class IntBag {
public:
    explicit IntBag(int v) : data_(new int(v)) {}
    // ── 三大件之一：拷贝构造（深拷贝）
    IntBag(const IntBag& other) : data_(new int(*other.data_)) {}
    // ── 三大件之二：拷贝赋值运算符
    IntBag& operator=(const IntBag& other) {
        if (this != &other) {           // ① 防自赋值：a = a 不出错
            *data_ = *other.data_;      // ② 复制内容，不复制地址
        }
        return *this;                   // ③ 返回自身，支持 a = b = c
    }
    // ── 三大件之三：析构函数
    ~IntBag() { delete data_; }

    int value() const { return *data_; }
    void set(int v) { *data_ = v; }
private:
    int* data_;
};

int main() {
    IntBag a(1);
    IntBag b = a;    // 深拷贝：b 有自己的堆内存
    b.set(99);       // 只改 b，不影响 a
    std::cout << a.value() << " " << b.value() << "\n";
    a = b;           // 拷贝赋值
    std::cout << a.value() << "\n";
    return 0;
}
▶ 预期输出
1 99
99

逐行解释

  • 第7行：new int(*other.data_)——先取别的对象堆上的值，再给自己另开一块堆内存放进去。两块内存从此互不相干。
  • 第9~14行：拷贝赋值的标准三步：this != &other 防自赋值；复制内容；return *this 返回自己。
  • 第26~27行：b 改成 99，a 仍是 1——深拷贝后互不影响，输出 1 99。
  • 第29行：a = b; 走拷贝赋值运算符，a 的堆内存内容变为 99。
  • Rule of Three：析构、拷贝构造、拷贝赋值——需要自定义其中一个，几乎就三个都需要（资源管理类尤其如此）。C++11 加入移动语义后扩展为 Rule of Five（第 9 章）。

变体对比

如果默认的逐成员复制刚好够用（没有资源需要管），C++11 起可以写 IntBag(const IntBag&) = default; 明确表达“我就是要默认行为”；而不该被拷贝的类则 =delete（示例 12）。现代 C++ 更推荐直接用 std::vector/智能指针管理资源，让“三大件”自动生成即正确（第 9、10 章）。

⚠ 易错点

拷贝赋值忘写 return *this; 无法支持 a = b = c 连等；忘写自赋值判断，遇到 a = a 时若实现是“先释放再复制”就会出事。这两处是阅卷常见扣分点。

9. static 成员：属于类，而不是对象

示例10：static 成员变量与静态成员函数

知识点：static 成员
#include <iostream>

class Counter {
public:
    Counter()  { ++count_; }                 // 每构造一个，计数 +1
    ~Counter() { --count_; }
    static int alive() { return count_; }    // 静态成员函数：没有 this
    static int count_;                       // 类内只是“声明”
};

int Counter::count_ = 0;                     // ⭐ 类外定义（分配存储），一般写在 .cpp

int main() {
    Counter a, b;
    std::cout << Counter::alive() << "\n";  // 用类名访问，不需要对象
    {
        Counter c;
        std::cout << c.alive() << "\n";      // 也可以通过对象访问
    }
    std::cout << Counter::count_ << "\n";
    return 0;
}
▶ 预期输出
2
3
2

逐行解释

  • 第8行：static int count_; 在类内只是声明——它说的是“所有 Counter 共享一个 count_”。
  • 第11行：必须在类外定义一次（分配存储），否则链接时报 undefined reference。整型常量有例外：static const int N = 10; 可以在类内直接初始化。
  • 第7行：静态成员函数没有 this 指针，只能访问静态成员；调用不需要任何对象：Counter::alive()。
  • 第15、18、20行：a、b 共享同一份 count_（值为 2）；c 出生变 3，c 析构后回到 2。

⚠ 易错点

“static 成员变量属于类，不属于任何对象”——每个对象里没有它的副本，sizeof 一个对象也统计不到它。判断题“每创建一个对象，static 成员都会重新初始化一次”为假。

10. 对象数组与按值传参的性能

示例11：对象数组的拷贝初始化 + 按值传参的代价

知识点：对象数组 / 传参方式高频考点
#include <iostream>
#include <string>

class Student {
public:
    explicit Student(std::string name) : name_(name) {
        std::cout << "构造 " << name_ << "\n";
    }
    Student(const Student& other) : name_(other.name_) {
        std::cout << "拷贝 " << name_ << "\n";
    }
private:
    std::string name_;
};

void save(Student s) {   // 按值传参：又要拷贝一次
    // ……保存 s 的逻辑（省略）
}

int main() {
    Student a("Alice");
    Student arr[3] = {a, a, a};   // 从左值拷贝初始化 3 个元素
    std::cout << "---\n";
    save(arr[0]);                 // 按值传参：拷贝构造
    return 0;
}
▶ 预期输出
构造 Alice
拷贝 Alice
拷贝 Alice
拷贝 Alice
---
拷贝 Alice

逐行解释

  • 第21行：a 先构造。
  • 第22行：对象数组的 3 个元素都从同一个左值 a 拷贝初始化——左值拷贝不允许被消除，所以必然是 3 次“拷贝 Alice”。
  • 第24行：save(arr[0]) 按值传参，形参再拷贝一次。
  • 对象数组离开作用域时同样按构造的相反顺序析构（本例未打印析构）。
性能提示：对象作函数参数时优先写 const Student&——按引用传递不调用拷贝构造，既快又安全（函数内改不了实参）。按值传参对大对象（内含 string、vector 的类）意味着一次完整的深拷贝加一次析构，循环里尤其要避免。

⚠ 易错点

“传对象就是把名字传过去”——错。按值传参每次调用都触发拷贝构造；传引用（&）传的是别名，一次拷贝都没有。

11. =default 与 =delete（C++11）

示例12：精确控制编译器生成的函数

知识点：=default / =deleteC++11
#include <iostream>

class Point {
public:
    Point() = default;                     // 显式要回默认构造（C++11）
    Point(int x, int y) : x_(x), y_(y) {}
    Point(const Point&) = delete;          // 禁止拷贝（C++11）
    Point& operator=(const Point&) = delete;
    int x_ = 0, y_ = 0;
};

class Id {
public:
    Id(int v) : v_(v) {}   // 定义了带参构造后，默认构造被“顶掉”
private:
    int v_;
};

int main() {
    Point p;           // OK：=default 提供的默认构造
    Point q(1, 2);
    // Point r = p;    // ⛔ 编译错误：拷贝被 =delete 禁止
    // Id u;           // ⛔ 编译错误：Id 没有默认构造
    std::cout << q.x_ << "\n";   // 使用 q，避免“未使用变量”警告
    return 0;
}
▶ 预期输出
1

逐行解释

  • 第5行：只要手写了任意构造函数（第 6 行），编译器就不再自动生成默认构造；=default 显式把它要回来，让 Point p; 合法。
  • 第7~8行：=delete 告诉编译器“这个函数不许用”——调用它的代码直接编译错误。典型用途：禁止拷贝的资源类、单例模式。
  • 第14行：Id 只定义了带参构造，隐式默认构造被顶掉——Id u; 报“没有默认构造”。这是构造函数最常见的意外。

变体对比

C++98 想禁止拷贝，只能把拷贝构造声明成 private 且不实现——报错信息晦涩、还要额外写一个 friend。=delete 一行搞定，报错直指“use of deleted function”。

12. 常见错误

1. 类定义结尾忘分号：class X { ... } 缺 ;，报错常出现在下一个定义处。修复：牢记 }; 收尾。
2. 在函数体内给 const / 引用成员赋值：编译错误。修复：const 成员、引用成员只能写进成员初始化列表。
3. 以为初始化列表按书写顺序执行：实际按声明顺序；让后面的成员给前面的成员当初值，读到的是未初始化内存。修复：列表顺序与声明顺序保持一致，避免成员间依赖。
带指针（资源）成员的类依赖编译器默认的拷贝——浅拷贝导致两个对象管理同一块内存，析构时双重释放，是未定义行为，典型症状是 double free 崩溃。修复：写全三大件做深拷贝（示例 9），或改用智能指针 / 容器托管资源（第 9、10 章）。
4. static 成员变量忘了类外定义：类内声明只是“报了个名字”，链接时报 undefined reference。修复：在类外（通常 .cpp 中）写 int Counter::count_ = 0;。
5. 对象按值传来传去：每次调用都拷贝构造 + 析构一次。修复：参数写 const T&。

更多同类报错见 编译错误博物馆（如 “undefined reference”“is private”），以及 速查表专区 的构造/析构顺序表；考前再过一遍 考试易错点 的“浅拷贝与三大件”专题。

13. C++ 标准差异

特性C++98C++11 及以后
成员初始化列表、构造/析构、三大件可用不变（扩展为 Rule of Five，第 9 章）
类内默认成员初始化 int x_ = 0;不可用可用
委托构造 Point() : Point(0,0) {}不可用可用
=default / =delete不可用（只能“private + 不实现”的老技巧）可用
static 成员（类外定义等规则）可用不变
拷贝消除（copy elision）：对“按值返回”或“用临时对象初始化”，C++98/11/14 允许编译器省掉拷贝但不强制，因此“拷贝构造打印几次”随编译器与优化等级而变；C++17 起对“从纯临时对象初始化”强制消除（如 Box b = Box("b3"); 只构造一次）。依赖拷贝次数的考题按基本规则（初始化 / 按值传参 / 按值返回）作答，工程中应避免依赖副作用次数。

本章小结

类把数据（private）和行为（public）捆在一起；成员按声明顺序初始化、对象按构造的相反顺序析构；管理资源的类必须写全“三大件”——否则默认的浅拷贝就是双重释放的 UB。
  • class 与 struct 唯一默认区别：默认 private / 默认 public。
  • 构造函数与类同名、无返回类型；成员初始化列表“出生即初始化”，const 成员与引用成员只能用它。
  • 成员初始化顺序 = 声明顺序，与列表书写顺序无关；成员间依赖初值的写法是 UB。
  • 析构函数 ~X() 在离开作用域 / delete 时调用，顺序与构造相反；成员在函数体之后自动析构。
  • 拷贝构造在初始化、按值传参、按值返回时触发；带指针成员必须深拷贝（Rule of Three）。
  • static 成员变量须类外定义；静态成员函数没有 this，只能访问静态成员。
  • 对象按值传参每次都拷贝——优先 const T&；=default / =delete（C++11）精确控制编译器生成的函数。
