第5章 指针与引用

指针直接操作内存地址，引用是对象的别名；本章讲指针算术、数组退化、const 组合与两者的选型，所有 UB 都会明确标出。

学习目标

  • 用 & 取地址、* 解引用，识别 int* a, b; 声明陷阱。
  • 用 nullptr 判空，区分它与 NULL、0；规避野指针与悬空指针。
  • 做指针算术：p + 1 移动 sizeof(T) 字节，*(p+i) 与 arr[i] 等价。
  • 解释数组退化：传参后 sizeof 失效，长度需单独传。
  • 区分 const int* p、int* const p、const int* const p 三种组合。
  • 说出引用的三条规则（必须初始化、不能重绑、无空引用），对比指针与引用的选型。

前置知识：第1章 变量与基本类型 与第4章“函数”。

1. 指针：存地址的变量

第 1 章说过，每个变量都有地址。指针就是一种“值为地址”的变量：int* p 的意思是“p 里存着一个 int 对象的地址”。两个专属运算符：& 取地址，* 解引用（顺着地址找到对象本身）。

示例1：取地址与解引用

知识点：指针基础入门必会
#include <iostream>

int main() {
    int a = 42;
    int* p = &a;              // p 存下 a 的地址

    std::cout << "a = " << a << "\n";
    std::cout << "*p = " << *p << "\n";   // 解引用：顺着地址找到 a
    *p = 50;                  // 通过 p 修改 a 本尊
    std::cout << "a = " << a << "\n";
    return 0;
}
▶ 预期输出
a = 42
*p = 42
a = 50

逐行解释

  • 第5行：&a 取出 a 的地址存入 p。从此“p 指向 a”。
  • 第8行：*p 读——顺着 p 里的地址找到 a，取出 42。
  • 第9行：*p = 50 写——顺着地址找到 a 并改写。通过指针修改的就是原对象，第 10 行的输出为证。

变体对比

sizeof(p) 是指针本身的大小（64 位平台 8 字节），与它指向的 int 多大无关。指针也分类型：int*、double*、char*……类型决定了“解引用时按什么解释、算术时跨多远”。

⚠ 声明风格坑：int* a, b;

int* a, b;    // a 是 int*，b 只是普通 int！
int *a, *b;   // 想都要指针就这样写
int* a;       // 最清晰：一行一个
int* b;

* 在语法上修饰变量名而不是类型——int* a, b; 等价于 int *a; int b;。

2. 空指针：nullptr、NULL 与 0

指针必须“有所指”才能解引用。表示“什么都不指”用空指针：C++11 起一律写 nullptr。

示例2：nullptr 与判空的习惯

知识点：空指针C++11
#include <iostream>

int main() {
    int* p = nullptr;            // 一开始就置空：明确“不指向任何对象”

    if (p == nullptr) {
        std::cout << "p 不指向任何对象\n";
    }
    // std::cout << *p;          // ⛔ 解引用空指针：UB（此处没有执行）

    int x = 7;
    p = &x;                      // 现在指向 x
    if (p != nullptr) {
        std::cout << "*p = " << *p << "\n";
    }
    return 0;
}
▶ 预期输出
p 不指向任何对象
*p = 7

逐行解释

  • 第4行：nullptr 是专门的空指针字面量，类型为 std::nullptr_t，只能转换成指针类型。
  • 第6~8行：使用指针前先判空——这是指针安全的必修课。
  • 第13行：p 已指向 x，判空通过后解引用才安全。

变体对比

delete 空指针是安全的（定义好的空操作），所以“delete 后置空”能让后续的防御性 delete 无害化（示例 7）。

⚠ 野指针：未初始化的指针

局部指针不初始化（int* p;）就是野指针：它的值是栈上残留的随机比特，“指向”哪里完全不可控。解引用野指针是未定义行为——可能崩溃、可能悄悄改坏别的变量、也可能在优化后表现完全错乱。空指针一解引用通常当场崩溃（容易发现问题），野指针却可能“看起来还在正常运行”地悄悄破坏数据。解引用空指针同样是 UB（通常表现为段错误崩溃）。规避三连：定义即初始化（int* p = nullptr;）、使用前判空、delete 后置空。
C++98 只有 NULL（宏，展开后是一个值为 0 的整数常量，通常就是 0）和字面量 0；C++11 起才有 nullptr。在 C 语言里 NULL 可以是 ((void*)0)，但 C++ 里不允许这样定义——这是 C/C++ 的差异之一。因为 0 既是整数又是合法的空指针常量，重载时容易出乱子，这正是引入 nullptr 的动机（见示例 3）。

示例3：nullptr 如何参与重载决议

知识点：nullptr 与重载高频考点
#include <iostream>

void f(int)   { std::cout << "f(int)\n"; }
void f(char*) { std::cout << "f(char*)\n"; }

int main() {
    f(nullptr);   // nullptr 只能转成指针类型 → f(char*)
    f(0);         // 整数 0 → 精确匹配 f(int)
    return 0;
}
▶ 预期输出
f(char*)
f(int)

逐行解释

  • 第7行：nullptr 的类型是 std::nullptr_t，能转换成任意指针类型，但不能转成 int——f(int) 根本不可行，唯一候选 f(char*) 胜出。
  • 第8行：0 是 int 字面量，精确匹配 f(int)。
  • 若写 f(NULL)：NULL 通常是整数 0，往往也会选中 f(int)——与“我想传空指针”的直觉相反。

变体对比

只有 void f(int); 一个候选时，f(nullptr) 是编译错误（nullptr 转不成 int）。

⚠ 易错点

判断题“NULL 和 nullptr 完全等价”为假：NULL 是值为 0 的整数常量（宏），nullptr 是独立的指针类型。C++11 起一律用 nullptr。

3. 指针算术：按元素跨度移动

指针支持 +、-、++、-- 和比较，但步长不是 1 字节：p + 1 前进 sizeof(T) 字节（T 是指针的元素类型）。指针只有指向数组元素（或同一数组内）时算术才有意义。

示例4：p+1、*(p+i) 与指针相减

知识点：指针算术高频考点
#include <iostream>

int main() {
    int arr[5] = {10, 20, 30, 40, 50};
    int* p = arr;                  // 指向首元素 arr[0]
    int* q = &arr[4];              // 指向最后一个元素

    std::cout << *p << " " << *(p + 1) << " " << *(p + 4) << "\n";
    ++p;                           // 向后移动一个 int（4 字节）
    std::cout << *p << " " << *(p + 2) << "\n";
    std::cout << q - p << "\n";    // 相差几个元素（不是字节！）
    return 0;
}
▶ 预期输出
10 20 50
20 40
3

逐行解释

  • 第5行：数组名在这里退化为指向首元素的指针，等价于 &arr[0]（退化详见第 4 节）。
  • 第8行：*(p + i) 与 arr[i] 完全等价——语言层面 arr[i] 本来就定义为 *(arr + i)。
  • 第9行：++p 后 p 从 arr[0]（地址 …1000）走到 arr[1]（地址 …1004）——只前进了 sizeof(int) = 4 字节。
  • 第11行：同类型指针相减得相差的元素个数（类型 ptrdiff_t）：q 在 arr[4]、p 在 arr[1]，差 3。不是字节数 12。

变体对比

double arr[5] 时，double* p 的 p + 1 前进 8 字节——步长永远等于 sizeof(元素类型)。指针也可以用 <、>、== 比较（常用于循环边界）。

⚠ 越界即 UB

指针算术只能在这条数组的范围内活动。arr[5] 之后已经出界，*(p + 5) 是未定义行为——标准只允许指针“指向数组元素或最后一个元素之后的位置”，且后者不能解引用。

4. 数组退化：长度丢了怎么办

数组作为实参传给函数时，退化为指向首元素的指针，长度信息丢失——函数内 sizeof(arr) 是指针大小。解决方案：把长度作为第二个参数一起传。

示例5：传数组必须传长度

知识点：数组退化高频考点
#include <iostream>

// 退化后长度信息丢失：把长度 n 一起传进来
int sum(const int* arr, int n) {
    int total = 0;
    for (int i = 0; i < n; ++i) {
        total += arr[i];      // arr[i] 即 *(arr + i)
    }
    return total;
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    std::cout << "main 里 sizeof(a) = " << sizeof(a) << "\n";
    std::cout << "sum = " << sum(a, 5) << "\n";
    return 0;
}
▶ 预期输出
main 里 sizeof(a) = 20
sum = 15

逐行解释

  • 第4行：形参 const int* arr 与写 int arr[] 完全等价；const 表示只读（第 5 节详解）。
  • 第7行：arr[i] 之所以能用，是因为 arr[i] 就是 *(arr + i)——指针加偏移再解引用。
  • 第14行：在定义处 sizeof(a) = 5 × 4 = 20；传进函数后只剩 8 字节的指针，长度 5 必须作为参数传入。

变体对比（进阶）

数组名与 &数组名 的类型不同：

int a[5];
int*  p1 = a;        // int*：指向首元素 a[0]
int (*p2)[5] = &a;   // int(*)[5]：指向“整个数组”
// 数值上 p1 与 p2 相同，但：
// p1 + 1 前进 sizeof(int)  = 4 字节
// p2 + 1 前进 sizeof(a)   = 20 字节

退化只发生在“数组名”这一个身份上，&a 不退化。想保留长度还可以用数组引用 int (&arr)[5]（第 4 章示例 5）。

⚠ 易错点

传长度参数时传错个数（如把字节数 20 当元素个数传）会越界读——属于未定义行为。习惯上传“元素个数”，并在函数内只信这个 n。

5. const 与指针：三种组合

const 和 * 的相对位置决定约束对象。口诀：“左定值，右定针”——const 在 * 左边，所指的值是常量；在 * 右边，指针本身是常量。

写法俗称指向可换？内容可改？
const int* p（等价 int const* p）指向常量的指针✔ 可以✘ 不行
int* const p常量指针✘ 不行✔ 可以
const int* const p双保险✘ 不行✘ 不行

示例6：三种组合逐一验证

知识点：const 与指针高频考点
#include <iostream>

int main() {
    int a = 10, b = 20;

    const int* p1 = &a;     // ① 指向常量的指针：内容只读
    // *p1 = 99;            // ⛔ 编译错误：不能通过 p1 改内容
    p1 = &b;                // ✔ 指向可以换

    int* const p2 = &a;     // ② 常量指针：指向不能换
    *p2 = 99;               // ✔ 内容可以改（a 变成 99）
    // p2 = &b;             // ⛔ 编译错误：不能换指向

    const int* const p3 = &b;   // ③ 双保险：都不能改
    std::cout << "*p1 = " << *p1 << "\n";
    std::cout << "*p2 = " << *p2 << "\n";
    std::cout << "a = " << a << " b = " << b << "\n";
    return 0;
}
▶ 预期输出
*p1 = 20
*p2 = 99
a = 99 b = 20

逐行解释

  • 第6~8行：p1 换指向到 b 合法，但 *p1 = 99 被编译器拒绝——这就是第 4 章只读参数 const std::string& 的指针版。
  • 第10~12行：p2 定义时必须初始化且永远指向 a；*p2 = 99 合法，把 a 改成 99。
  • 第14行：p3 两个方向都锁死，定义时必须初始化。
  • 第17行：a 已被 *p2 改成 99，所以输出 a = 99；p1 现在指着 b。

变体对比

把 int* 赋给 const int* 不需要任何转换（承诺加严，安全）；反方向（去掉 const）要 const_cast，且改写真正声明为 const 的对象是 UB——一律别做。

⚠ 易错点

int* const p 与 const int* p 中文都带“常量”二字，极易混。答题技巧：从右往左读声明——p is a const pointer to int（指针常量）；p is a pointer to const int（指向常量）。

6. 悬空指针：指向已消失的内存

示例7：悬空指针的三种来源（UB 示范）

未定义行为示范
#include <iostream>

int* getAddr() {
    int local = 42;
    return &local;      // ⛔ local 在函数返回时销毁
}

int main() {
    int* p = getAddr(); // p 从此悬空
    // std::cout << *p; // ⛔ 解引用悬空指针：UB，不写不考

    int* q = new int(5); // new：在堆上分配（后续章节详讲）
    delete q;            // 内存已归还系统
    // std::cout << *q;  // ⛔ 同样悬空：UB
    // delete q;         // ⛔ 双重 delete：UB
    q = nullptr;         // ✔ 好习惯：delete 后立刻置空
    return 0;
}

⚠ 为什么没有“预期输出”？

悬空指针指向的对象已经销毁。解引用悬空指针是未定义行为：可能崩溃、可能读到垃圾、可能“碰巧”正常——因此本例不给出任何预期输出，考试也不允许以它的结果为答案。三种典型来源：① 返回局部变量的地址（第 5 行，g++ -Wall 会报 warning: address of local variable 'local' returned [-Wreturn-local-addr]）；② delete 之后继续解引用；③ delete 之后再 delete（双重释放，可能破坏堆结构）。注意：delete 一个空指针是安全的（定义好的空操作），所以第 16 行“delete 后置空”是好习惯——但置空防不住“别的指针也指向同一块内存”的情况，根治靠设计。

7. 引用：对象的别名

第 4 章已经用过引用参数，现在正式介绍它。引用的三条铁律：① 定义时必须初始化；② 绑定后不能“重绑”（一切操作都作用于被绑对象）；③ 不存在空引用。它在语言层面就是别名——底层常由编译器用指针实现，但那是实现细节，标准只规定语义。

示例8：引用是别名，不是“可换的指针”

知识点：引用基础高频考点
#include <iostream>

int main() {
    int a = 1;
    int& r = a;        // 定义引用时必须初始化
    r = 100;           // 给 r 赋值就是给 a 赋值
    std::cout << "a = " << a << "\n";

    int b = 2;
    r = b;             // 不是重新绑定！是把 b 的值赋给 a
    std::cout << "a = " << a << " b = " << b << "\n";
    std::cout << (&r == &a ? "同一对象" : "不同对象") << "\n";
    return 0;
}
▶ 预期输出
a = 100
a = 2 b = 2
同一对象

逐行解释

  • 第5行：int& r = a;——r 从此是 a 的别名，不占新的“逻辑”对象。
  • 第6行：r = 100 完全等价于 a = 100。
  • 第10行：最容易错的行——r = b 不是让 r 改绑到 b，而是把 b 的值 2 拷贝给 a。引用一经绑定，终身不改。
  • 第12行：对 r 取地址得到的就是 a 的地址——别名与本尊是同一块内存。

变体对比

同样的声明陷阱：int& r = a, b; 里 b 是普通 int，不是引用（& 同样只修饰 r）。另外引用绑定后 sizeof(r) 等于被绑对象的大小（这里是 4），而 sizeof(int*) 恒为指针大小。

⚠ 返回局部引用同样是 UB

引用作为返回值时，规则与第 4 章示例 10 相同：绝不能返回局部变量的引用——函数返回后局部变量销毁，引用悬空，使用它是未定义行为。合法的返回引用对象：引用形参、静态/全局变量。

8. 指针 vs 引用：何时用哪个

对比点指针引用
可否“什么都不指”可以（nullptr）不存在空引用
定义时必须初始化否（但不初始化就是野指针）必须
之后可否改变指向可以重新赋值不能重绑
指针算术支持（p+1 等）不支持
多级形式int**、int*** 都有没有二级引用
使用方式要 *p 解引用、-> 访问成员像原对象一样直接用
何时选它可能为空、需要换目标、遍历内存对象必然存在、要别名词义

同一个 swap 的两种写法：

指针版：能干，但到处是 * 和 &

void swapP(int* px, int* py) {
    int t = *px;
    *px = *py;
    *py = t;
}
int main() {
    int a = 1, b = 2;
    swapP(&a, &b);   // 调用要取地址
}

引用版：C++ 首选

void swapR(int& rx, int& ry) {
    int t = rx;
    rx = ry;
    ry = t;
}
int main() {
    int a = 1, b = 2;
    swapR(a, b);     // 像传值一样自然
}

两者效果一致；引用版调用自然、不可能“忘了解引用”，参数语义上还承诺“必然有所指”。指针版胜在能表达“这里可能没有对象（空）”或“目标会换”的语义——函数参数的默认选择是引用，只有在“可空/可换/遍历内存”时才换指针。

示例9：综合运用——用引用/指针带回多个结果

综合
#include <iostream>

// 引用版：结果直接写进实参
void divModRef(int a, int b, int& q, int& r) {
    q = a / b;
    r = a % b;
}

// 指针版：传入结果变量的地址
void divModPtr(int a, int b, int* q, int* r) {
    *q = a / b;
    *r = a % b;
}

int main() {
    int q = 0, r = 0;
    divModRef(17, 5, q, r);
    std::cout << "引用版: 商=" << q << " 余=" << r << "\n";
    divModPtr(17, 5, &q, &r);
    std::cout << "指针版: 商=" << q << " 余=" << r << "\n";
    return 0;
}
▶ 预期输出
引用版: 商=3 余=2
指针版: 商=3 余=2

逐行解释

  • 第17、19行：函数要“带回”两个结果（商和余数），返回值不够用——用输出参数：引用版直接传变量，指针版传地址。
  • 第19行：指针版调用要写 &q, &r——漏写会得到类型不匹配的编译错误（编译器能拦住，比 C 语言时代安全些）。
  • 第18、20行：两次调用后 q=3、r=2（17 = 5×3 + 2），结果完全一致。

变体对比

输出参数也可以用 const int* 只读传入、非 const 引用写回混合使用。规则：只读参数加 const 引用，写回参数用非 const 引用，可空场景才用指针。

⚠ 易错点

判断题“引用参数 = 传值”为假；判断题“指针参数调用时不用取地址”为假。两者都在考“是否理解间接访问”。

9. 二级指针：指向指针的指针

指针自己也是变量、也有地址，所以可以有指向指针的指针。int** pp 解引用一次得到 int*，解引用两次才得到 int。这里点到为止，认识记号即可。

示例10：int** 与 ** 解引用

知识点：二级指针
#include <iostream>

int main() {
    int a = 7;
    int* p = &a;       // 一级指针：指向 int
    int** pp = &p;     // 二级指针：指向“指向 int 的指针”

    std::cout << **pp << "\n";   // 解引用两次：pp→p→a
    **pp = 99;                   // 通过二级指针修改 a
    std::cout << a << "\n";
    return 0;
}
▶ 预期输出
7
99

逐行解释

  • 第6行：&p 取的是“指针变量 p”自己的地址，类型是 int**。
  • 第8行：*pp 得到 p（值为 a 的地址），再 * 一次得到 a。
  • 第9行：**pp = 99 沿链条改写 a 本尊。

变体对比

main 还有一种带参数的写法：int main(int argc, char* argv[])。argv 是“若干个字符串（char*）”的数组，退化后就是 char**：argv[0] 是程序名、argv[1] 是第一个命令行参数。这是二级指针最常见的现身方式。

⚠ 易错点

几颗 * 就要解引用几次：拿 *pp（一个 int*）直接当 int 用是类型错误。判断题“int** 可以赋给 int*”为假——类型不同，不自动转换。

11. 常见错误

1. 解引用野指针：int* p; *p = 1; —— p 未初始化，指向随机地址，写入是未定义行为。修复：int* p = nullptr; 或直接指向合法对象。
2. 解引用空指针：int* p = nullptr; cout << *p; —— 通常表现为段错误崩溃，标准定性为 UB。使用前必须判空。
3. 悬空指针：返回局部变量地址、delete 后继续解引用或双重 delete，都是 UB。习惯：delete 后置空；谁拥有内存谁来释放（后续章节展开）。
4. 声明陷阱：int* a, b; 里 b 是普通 int。一行一个声明，或写 int *a, *b;；引用同理 int& r = a, b; 的 b 也不是引用。
5. 函数内用 sizeof 求数组长度：数组传参退化后 sizeof(arr) 是指针大小（64 位平台 8）。必须把长度作为参数传入（或用数组引用/容器）。
6. 把赋值当重绑：int& r = a; r = b; 不会让 r 指向 b，而是把 b 的值拷贝给 a。引用不能重绑；需要“换目标”的语义就该用指针。

更多同类错误见 编译错误博物馆（如“cannot convert”“invalid conversion”），以及 考试易错点 中的指针专题；常用写法可查 速查表。

本章小结

指针存地址、引用是别名。安全口诀：定义即初始化、使用前判空、delete 后置空；“左定值，右定针”分清 const；数组传参退化，长度必须单独传；UB（野指针、空指针、悬空指针）不考输出，只考规避。
  • & 取地址、* 解引用；int* a, b; 的 b 是普通 int。
  • nullptr 优于 NULL/0；未初始化的指针是野指针，解引用是 UB。
  • p+1 前进 sizeof(T) 字节；arr[i] 就是 *(arr+i)；指针相减得元素个数。
  • 数组退化：传参后长度丢失，函数内 sizeof 失效；&a 与 a 类型不同。
  • const 三组合：const int*（值只读）、int* const（指向锁定）、双保险。
  • 悬空指针三种来源：局部地址带出、delete 后用、双重 delete。
  • 引用三铁律：必须初始化、不能重绑、无空引用；返回局部引用是 UB。
  • 选型：默认引用；可空/可换目标/遍历内存才用指针；char** argv 是二级指针的常见形态。
