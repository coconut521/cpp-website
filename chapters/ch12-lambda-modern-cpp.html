第12章 Lambda 与现代 C++

本章讲 Lambda 表达式（C++11 引入、就地定义的匿名函数）的语法与捕获规则、与 STL 算法的配合，最后简介 C++14/17/20 的相关现代特性。

学习目标

  • 写出 lambda 的完整语法 [捕获](参数) -> 返回类型 { 函数体 }，说出每一部分的作用。
  • 区分 [x, &y]、[=]、[&]、[=, &total] 四类捕获写法，理解“按值捕获发生在定义那一刻”。
  • 解释按值捕获的副本默认是 const、mutable 改变的是什么，说明 [this] 与 [*this]。
  • 识别“按引用捕获 + lambda 逃逸出作用域”的悬空引用陷阱及其两种修法。
  • 用 lambda 给 std::sort 写自定义比较器，用 count_if、for_each 处理数据；说清 lambda、函数指针、std::function 三者的关系。
  • 使用 C++17 的结构化绑定、if 带初始化、std::optional、std::string_view、CTAD；了解 C++20 的 concepts、ranges、<=>、指定初始化器。

前置知识：第1章 变量与基本类型（auto、列表初始化）；STL 容器与算法（vector、map、sort）。

1. Lambda：就地定义的“无名函数”

Lambda（希腊字母 λ）本质上是一个没有名字的函数对象：编译器看到 lambda 表达式，会生成一个匿名的“闭包类型”，并创建该类型的一个对象（称为闭包）。它的类型是编译器私有的、独一无二的，只能用 auto（或 std::function，见第 7 节）来接。完整语法：

[捕获列表] (参数列表) -> 返回类型 { 函数体 }
    │          │          │         │
    │          │          │         └─ 要执行的代码
    │          │          └─ 通常省略（自动推导）；要写时形如 -> double
    │          └─ 和普通函数一样；无参数可写成 ()
    └─ 决定怎么“带走”外部变量：[x, &y] / [=] / [&] / [=, &total]
组成部分例子作用
捕获列表 [][x, &y]、[=]、[&]、[=, &total]决定如何捕获外部局部变量（本章核心）
参数列表 ()(int a, int b)与普通函数相同；无参时 () 可省略
返回类型 -> T-> double通常可省略（自动推导）；返回值类型不一致时必须写
函数体 {}{ return a + b; }与普通函数相同

lambda 出现前，给算法传“一段逻辑”必须先定义函数或函数对象（仿函数），逻辑与调用处分离。

❌ C++98：先定义函数对象（仿函数），再传给算法

struct Between60And90 {
    bool operator()(int s) const {
        return s >= 60 && s < 90;
    }
};
// 使用处离定义处很远：
int n = std::count_if(v.begin(), v.end(),
                      Between60And90());

✅ C++11：lambda 就地定义，逻辑就在调用处

int n = std::count_if(v.begin(), v.end(),
    [](int s) { return s >= 60 && s < 90; });

示例1：最简形式与完整形式

知识点：Lambda 语法入门必会
#include <iostream>

int main() {
    auto add = [](int a, int b) { return a + b; };    // 最简形式：返回类型自动推导为 int
    auto ratio = [](double a, double b) -> double {   // 完整形式：显式写出返回类型
        return a / b;
    };

    std::cout << add(2, 3) << "\n";     // 5
    std::cout << ratio(7, 2) << "\n";   // 3.5
    [] { std::cout << "hi\n"; }();      // 无参、无捕获：定义后立即调用
    return 0;
}
▶ 预期输出
5
3.5
hi

逐行解释

  • 第4行：[](int a, int b) { return a + b; } 是 lambda 表达式，auto add 接住闭包对象。返回类型从 a + b 自动推导为 int。
  • 第5~7行：-> double 显式指定返回类型。参数是 double，所以 ratio(7, 2) 里的 7、2 先转成 7.0、2.0，7.0 / 2.0 = 3.5（不再是第 2 章的整数除法）。
  • 第11行：[] { ... }()——定义之后紧跟一对 ()，当场调用。这种“立即调用”常用于给一段独立逻辑起个“局部作用域”。

变体对比

返回类型不一致时必须显式写：auto f = [](int x) -> double { if (x > 0) return 1; return 0.5; }; 合法；若去掉 -> double，两个 return 一个是 int 一个是 double，直接编译错误。

⚠ 易错点

闭包类型独一无二：auto f = [](int x) { return x; }; 之后写 f = [](int x) { return x; }; 是编译错误——两个 lambda 即使写得一模一样，类型也不同。想让变量能重新赋值，用 std::function（见示例 9）。

Lambda 表达式是 C++11 引入的；用 g++ -std=c++98 编译示例 1 会直接报错。另注意：全局变量、静态变量不需要捕获就能在 lambda 里直接使用，捕获列表只管“局部变量”。
本章示例统一按 C++17 编译：g++ -std=c++17 main.cpp -o main（建议加 -Wall -Wextra）。示例 12 是 C++20 专属语法，需要 -std=c++20。

2. 捕获列表

lambda 的函数体里想用外部的局部变量，必须在 [] 里写明捕获方式。常用写法四类：

写法含义
[x, &y]逐个列出：x 按值拷贝，y 按引用（用本体）
[=]用到的外部变量全部按值拷贝
[&]用到的外部变量全部按引用
[=, &total]混合：默认按值，& 例外项按引用

示例2：逐个列出 [x, &y]

知识点：捕获列表高频考点
#include <iostream>

int main() {
    int x = 10;
    int y = 20;

    auto byVal = [x]() { return x; };            // 按值捕获：拷贝一份 x 存进闭包
    auto byRef = [&y]() { y += 1; return y; };   // 按引用捕获：闭包里记的是 y 本体

    x = 99;                    // 修改原变量
    std::cout << byVal() << "\n";
    byRef();                   // 通过引用改了 y 本体
    std::cout << y << "\n";
    return 0;
}
▶ 预期输出
10
21

逐行解释

  • 第7行：[x] 在定义那一刻把 x 的值 10 拷贝进闭包对象。此后 x 再怎么变，副本都是旧快照。
  • 第8行：[&y] 不拷贝，闭包里存的是 y 的引用（可以理解为地址），之后读写都是 y 本体。
  • 第10~11行：x 改成 99，但 byVal() 读自己的副本 → 输出 10。
  • 第12~13行：byRef() 执行 y += 1，y 本体变 21 → 输出 21。

⚠ 易错点

按值捕获是定义时刻的快照：先捕获、后修改原变量，读到的仍是旧值（本例输出 10）。

示例3：默认捕获 = 与 &，以及混合写法 [=, &total]

知识点：默认捕获与混合捕获高频考点
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3};
    int total = 0;
    int factor = 10;

    auto addMul = [factor, &total](int n) {  // 逐个列出：factor 按值，total 按引用
        total += n * factor;
    };
    addMul(v[0]);              // total = 1*10 = 10
    addMul(v[1]);              // total = 30
    std::cout << total << "\n";

    auto addAll = [&](int n) { total += n; };  // [&]：用到的全部按引用
    addAll(v[2]);              // total = 33
    std::cout << total << "\n";

    auto snapshot = [=, &total] {  // [=]：默认按值，total 例外按引用
        total += factor;
        return factor;
    };
    snapshot();
    std::cout << total << " " << factor << "\n";
    return 0;
}
▶ 预期输出
30
33
43 10

逐行解释

  • 第9~13行：[factor, &total]——factor 拷贝一份（值 10），total 按引用。两次调用后 total = 10 + 20 = 30。
  • 第16~18行：[&] 默认按引用：函数体用到的局部变量（这里只有 total）都以本体参与，total 变 33。
  • 第20~25行：[=, &total]——默认按值（factor 拿到副本 10），total 例外按引用。total += factor 后 total = 43；factor 的原变量从未被写，仍是 10。

⚠ 易错点

混合写法的方向别记反：[=, &total] 是“默认值、它引用”；[&, total] 才是“默认引用、它按值”。另外捕获默认符（= 或 &）必须写在捕获列表最前面，写成 [&total, =] 直接编译错误。

❌ 目标：让 inc() 累加 n —— 按值捕获做不到

int n = 1;
auto inc = [n]() mutable {
    ++n;            // 改的只是闭包里的副本
};
inc();
inc();
std::cout << n;     // 输出 1：原变量纹丝不动

✅ 同一目标 —— 按引用捕获正确完成

int n = 1;
auto inc = [&n] {
    ++n;            // 改的是 n 本体
};
inc();
inc();
std::cout << n;     // 输出 3：原变量被累加两次
按值捕获适合“只读快照”：lambda 可能被存起来晚点用、或多线程里不想共享变量。按引用捕获适合“就地修改”或拷贝大对象代价高时——但必须保证被引用变量的寿命覆盖 lambda 的寿命（第 6 节的陷阱正源于此）。

3. mutable：按值捕获的副本默认是 const

按值捕获进闭包的每个副本，默认带 const——函数体里不能修改它们（否则编译错误）。想改，加 mutable：mutable 解除的是“副本”的 const，原变量仍然不受影响。

示例4：mutable 只解除副本的 const

知识点：mutable高频考点
#include <iostream>

int main() {
    int n = 1;

    auto counter = [n]() mutable {  // mutable：允许修改“自己的副本”
        n += 1;
        return n;
    };
    // auto bad = [n] { n += 1; };   // ← 编译错误：副本默认 const

    std::cout << counter() << "\n";  // 第一次调用：副本 1→2
    std::cout << counter() << "\n";  // 第二次调用：还是那个闭包，副本 2→3
    std::cout << n << "\n";          // 原变量从未被改：仍是 1
    return 0;
}
▶ 预期输出
2
3
1

逐行解释

  • 第6行：闭包对象里存着一份 n 的拷贝；mutable 把这份拷贝从 const 变为可写。
  • 第12~13行：counter 是同一个闭包对象，两次调用自增的是同一份副本：1→2、2→3。副本的状态在调用之间保留。
  • 第14行：原变量 n 从头到尾是 1——mutable 与它无关。

变体对比

若只想“用 n 算个数”不改副本，根本不用 mutable：auto next = [n] { return n + 1; };。真正要改原变量时，用按引用捕获 [&n] 而不是 mutable。

⚠ 易错点

判断题陷阱：“加了 mutable，lambda 就能修改外面的变量”——假。mutable 只让闭包内的副本可写，外面的原变量永远不变。

关于捕获 this，一句话记住：在成员函数里写 [this]，捕获的是当前对象的地址，lambda 内可直接访问成员；C++17 起还可写 [*this]，把整个对象按值拷贝进闭包（之后原对象怎么改都不影响拷贝）。[this] 同样有寿命问题：对象先销毁、lambda 还在，就悬空了。另注意 C++20 起 [=] 隐式捕获 this 已被标记为弃用，要显式写 [this] 或 [*this]。

4. C++14：泛型 Lambda 与初始化捕获

示例5：参数写 auto 的泛型 Lambda，与 [v = std::move(v)] 初始化捕获

知识点：泛型 Lambda / 初始化捕获C++14
#include <iostream>
#include <string>
#include <utility>

int main() {
    auto g = [](auto a, auto b) { return a + b; };   // 泛型 Lambda（C++14）
    std::cout << g(2, 3) << "\n";                    // 5
    std::cout << g(1.5, 2) << "\n";                  // 3.5
    std::cout << g(std::string("ab"), std::string("cd")) << "\n";  // abcd

    std::string s = "payload";
    auto take = [msg = std::move(s)] { return msg; }; // 初始化捕获（C++14）
    std::cout << take() << "\n";                      // payload
    return 0;
}
▶ 预期输出
5
3.5
abcd
payload

逐行解释

  • 第6行：参数写成 auto 就是泛型 Lambda（C++14）：调用时按实参推导，一个 lambda 通吃 int、double、string。
  • 第7~9行：g(2,3) 得 int 5；g(1.5,2) 中 a 推导为 double、b 为 int，相加得 3.5；两个 string 相加得 "abcd"。
  • 第11~12行：初始化捕获 [msg = std::move(s)]：在闭包里新建成员 msg，用 std::move(s) 初始化——把字符串的内容“搬”进闭包而不是拷贝。等号左边是新成员的名字，右边才是外层作用域的表达式。
  • 第13行：take() 返回 msg 的拷贝 → payload。此后 s 处于“被移动后”的合法但未指定状态，不要再依赖它的值。

变体对比：泛型 Lambda + if constexpr（C++17）

// 片段（需 #include <type_traits>，-std=c++17）
auto describe = [](auto x) {
    if constexpr (std::is_integral_v<decltype(x)>)
        return "整数";
    else
        return "非整数";
};
std::cout << describe(42);   // 整数（另一个分支根本不参与编译）

if constexpr 是编译期分支：条件为假的分支直接丢弃，这让它能安全地写在泛型代码里。

⚠ 易错点

初始化捕获写成 [msg = msg]（想在原地用同名变量）没问题，但 [std::move(s)] 这种没写新名字的会被当成“捕获 s”，不是移动语义。标准写法就是“新名字 = 表达式”。

参数 auto 的泛型 Lambda 与初始化捕获 [v = std::move(v)] 都是 C++14 新增；if constexpr 是 C++17 新增。编译示例 5 至少需要 -std=c++14，其变体需要 -std=c++17。

5. Lambda 与 STL 算法

lambda 的最大用处是给 STL 算法传“一小段判断/操作”。本章用到的算法都在 <algorithm> 里，别忘了 #include <algorithm>。

示例6：std::sort 自定义比较器

知识点：sort 自定义比较常用套路
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<int> nums{5, 1, 4, 2, 3};
    std::sort(nums.begin(), nums.end(),
              [](int a, int b) { return a > b; });  // 自定义：降序
    for (int n : nums) std::cout << n << " ";
    std::cout << "\n";

    std::vector<std::string> ws{"watermelon", "fig", "banana", "kiwi"};
    std::sort(ws.begin(), ws.end(),
              [](const std::string& a, const std::string& b) {
                  return a.size() < b.size();       // 按长度升序
              });
    for (const std::string& w : ws) std::cout << w << " ";
    std::cout << "\n";
    return 0;
}
▶ 预期输出（行尾各有一个打印时补的空格）
5 4 3 2 1 
fig kiwi banana watermelon

逐行解释

  • 第9~10行：比较器的语义是“a 应排在 b 前面时返回 true”。a > b 即“大的在前”→ 降序：5 4 3 2 1。
  • 第14~18行：按字符串长度升序。四个词长度各不相同（3、4、6、10），结果确定为 fig、kiwi、banana、watermelon。
  • 打印行：每个元素后补一个空格，所以两行末尾各有一个空格（预期输出已如实写出）。

变体对比

std::sort 不保证相等元素的相对顺序；若需要稳定，用 std::stable_sort。另外比较器常写成 const& 参数（如本例字符串版），避免拷贝大对象。

⚠ 易错点

想降序却写成 a < b：不是编译错误，只是排成了升序——“结果与预期相反”类错误。写 >= 更严重：那是未定义行为（见“常见错误”一节）。

示例7：count_if 统计 + for_each 累计

知识点：count_if / for_each算法
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> scores{90, 55, 76, 48, 88, 61};

    int pass = std::count_if(scores.begin(), scores.end(),
                             [](int s) { return s >= 60; });
    std::cout << "及格人数: " << pass << "\n";   // 4

    int sum = 0;
    std::for_each(scores.begin(), scores.end(),
                  [&sum](int s) { sum += s; });   // 按引用捕获，向外部累计
    std::cout << "总分: " << sum << "\n";          // 418
    return 0;
}
▶ 预期输出
及格人数: 4
总分: 418

逐行解释

  • 第8~10行：count_if 返回“谓词为 true”的元素个数：90、76、88、61 共 4 个及格。
  • 第13~14行：for_each 对每个元素执行 lambda；[&sum] 按引用捕获，让 lambda 能把结果累加到外部。90+55+76+48+88+61 = 418。
  • 同样的累加用范围 for 也行：for (int s : scores) sum += s;——for_each 的价值在于能配合“先 filter 再算”的算法链。

⚠ 易错点

count_if 的谓词应当是“只读”的：标准不保证它被调用几次、以什么顺序调用（实现还会拷贝谓词）。在谓词里自增计数器这类“有状态”写法，结果是靠不住的。

6. 生命周期陷阱：lambda 比局部变量活得久

按引用捕获只存“地址”，不延长被引用变量的寿命。如果 lambda 被带回/传到原作用域之外再调用，它手里的引用就成了悬空引用——与第 5 章返回局部变量的引用是同一类错误。

示例8：返回“按引用捕获局部变量”的 lambda（UB 示范）

未定义行为示范
#include <functional>
#include <iostream>

std::function<int()> makeCounter() {
    int n = 0;                        // 局部变量
    return [&n] { return ++n; };      // ⛔ 按引用捕获了 n
}

int main() {
    auto c = makeCounter();           // makeCounter 已返回，n 已销毁
    std::cout << c() << "\n";         // ⛔ 未定义行为：n 是悬空引用
    return 0;
}

⚠ 为什么没有“预期输出”？

makeCounter 返回后，其栈帧回收，局部变量 n 销毁；闭包里却还保存着对 n 的引用。之后调用 c() 就是解引用一个已销毁的变量——这是未定义行为：可能崩溃、可能“碰巧”输出 1、可能输出垃圾值、也可能被优化器改成任何样子。因此本例不给预期输出，考试也不允许拿它的结果当答案。修复：① 按值捕获 [n]() mutable { return ++n; }（副本随闭包走，见示例 4）；② 保证被引用变量活得比 lambda 久（例如 lambda 只在原作用域内使用，或引用的对象是 static/全局/堆上的）。

修复版（可编译，行为确定）

std::function<int()> makeCounterFixed() {
    int n = 0;
    return [n]() mutable { return ++n; };  // ✅ 按值拷进闭包，副本随闭包存活
}

注意：按值捕获发生在定义时刻（此时 n 还是活的，拷贝合法），之后原 n 销毁也无所谓——闭包用的是自己的副本。

同类高频错误：把 [&] 的 lambda 存进容器、注册成回调、传给其他线程——只要它离开了被捕获变量的作用域，引用即悬空。规则：lambda 要逃出作用域，就按值捕获。

7. Lambda、函数指针与 std::function

一句话关系：无捕获的 lambda 可以隐式转换成同签名的函数指针；有捕获的 lambda 携带状态、转不成函数指针，要装进 std::function（能装下“任何可以像函数那样调用的东西”，需要 #include <functional>）。

示例9：无捕获 lambda 可转函数指针；有捕获的用 std::function

知识点：可调用对象
#include <functional>
#include <iostream>

int apply(int x, int (*f)(int)) {   // 参数：老式函数指针
    return f(x);
}

int main() {
    auto square = [](int x) { return x * x; };   // 无捕获 lambda
    int (*fp)(int) = square;                     // ✅ 可隐式转换为函数指针
    std::cout << apply(5, fp) << "\n";           // 25
    std::cout << apply(6, square) << "\n";       // 36（直接传也行）

    int base = 10;
    auto addBase = [base](int x) { return base + x; };  // 有捕获 lambda
    std::function<int(int)> g = addBase;         // ✅ 装进 std::function
    std::cout << g(5) << "\n";                   // 15

    std::function<int(int)> h = square;          // std::function 也能装无捕获 lambda
    std::cout << h(7) << "\n";                   // 49
    // int (*bad)(int) = addBase;                // ⛔ 编译错误：有捕获不能转函数指针
    return 0;
}
▶ 预期输出
25
36
15
49

逐行解释

  • 第10~12行：无捕获的 square 没有状态，编译器允许它退化成普通函数指针 int(*)(int)，因此能赋给 fp、也能直接传给 apply。
  • 第15~17行：addBase 捕获了 base（闭包里存着 10），转不成函数指针；std::function<int(int)> 用“类型擦除”装下任何 int(int) 形状的可调用对象，g(5) = 10 + 5 = 15。
  • 第20行：三种东西都能装进 std::function：函数指针、无捕获 lambda、有捕获 lambda——这就是它常被用作“回调参数类型”的原因。

变体对比

模板参数也能接任何可调用对象且零额外开销：template <class F> int apply2(int x, F f) { return f(x); }——apply2(3, addBase) 合法。考试记结论：函数指针最窄，std::function 最通用。

⚠ 易错点

std::function 的灵活性有代价（类型擦除，可能引入额外间接调用），性能敏感的接口优先用模板参数或无捕获 lambda。

8. 现代 C++ 精选（C++17）

C++17 的特性让代码少写类型、少写临时变量，并把“有没有值”表达清楚。

示例10：结构化绑定 + if / switch 带初始化

知识点：结构化绑定C++17
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> ages{
        {"Li", 20}, {"Wang", 21}, {"Zhao", 19}};

    for (const auto& [name, age] : ages) {   // 结构化绑定（C++17）
        std::cout << name << " -> " << age << "\n";
    }

    if (auto it = ages.find("Wang"); it != ages.end()) {  // if 带初始化（C++17）
        std::cout << "Wang 的年龄是 " << it->second << "\n";
    } else {
        std::cout << "查无此人\n";
    }

    switch (int n = 21 % 4; n) {             // switch 带初始化（C++17）
        case 1: std::cout << "余数是 1\n"; break;
        default: std::cout << "余数不是 1\n"; break;
    }
    return 0;
}
▶ 预期输出
Li -> 20
Wang -> 21
Zhao -> 19
Wang 的年龄是 21
余数是 1

逐行解释

  • 第9~11行：auto [name, age] 把每个键值对（pair）的 first/second 直接命名为 name、age。map 按键升序遍历："Li" < "Wang" < "Zhao"。
  • 第13行：if (init; cond)——it 的作用域被限制在整个 if/else 里，不会泄漏到函数其他地方。
  • 第19行：switch (init; cond) 同理：n = 21 % 4 = 1，命中 case 1。

变体对比

C++17 之前只能 for (const auto& kv : ages) std::cout << kv.first << kv.second;——结构化绑定让“先取 pair 再取成员”的中间名字消失了。

⚠ 易错点

const auto& [name, age] 是引用绑定，不能通过它们修改元素；写成 auto [name, age] 才是拷贝一份。别把“绑定”当成“又复制了一遍数据”。

示例11：std::optional、std::string_view 与 CTAD

知识点：optional / string_view / CTADC++17
#include <iostream>
#include <optional>
#include <string_view>
#include <utility>
#include <vector>

std::optional<int> findIndex(const std::vector<int>& v, int target) {
    for (std::size_t i = 0; i < v.size(); ++i)
        if (v[i] == target) return static_cast<int>(i);
    return std::nullopt;                 // “没找到”：不再用 -1 冒充
}

int main() {
    std::vector v{10, 20, 30};           // CTAD：推导为 vector<int>（C++17）
    std::pair p{1, 2.5};                 // CTAD：推导为 pair<int, double>

    if (auto idx = findIndex(v, 20))     // optional 可直接当条件用
        std::cout << "找到，下标 " << *idx << "\n";
    if (!findIndex(v, 99))
        std::cout << "99 不存在\n";

    std::string_view sv = "modern c++";  // 只读视图，不拷贝数据
    std::cout << sv.substr(0, 6) << "\n";   // modern
    std::cout << p.first << " " << p.second << "\n";  // 1 2.5
    return 0;
}
▶ 预期输出
找到，下标 1
99 不存在
modern
1 2.5

逐行解释

  • 第7~11行：std::optional<int> = “可能有一个 int”。找到就返回下标，找不到返回 std::nullopt——比“返回 -1 表示没找到”的魔法值安全得多，类型系统替你记住“可能没有”。
  • 第14~15行：CTAD（类模板实参推导）：模板参数从初始值推出来，std::vector<int>、std::pair<int, double> 不用再手写尖括号。
  • 第17~20行：if (auto idx = ...) 利用 optional 的“有没有值”语义；*idx 取出里面的 1。
  • 第22~23行：string_view 是字符串的只读视图（指针 + 长度），切片 substr 不产生任何拷贝。

变体对比

不想写 if 判断？int idx = findIndex(v, 99).value_or(-1);——没找到就给兜底值 -1，一行搞定。注意 string_view 不拥有数据：它引用的字符串必须活得比它久，否则和悬空引用同病。

⚠ 易错点

对空的 std::optional 使用 * 或 ->（如 *findIndex(v, 99)）是未定义行为——它假定“一定有值”。取值前先判 if (opt)，或用 value_or(兜底值)、opt.value()（没值时抛异常而非 UB）。

9. C++20 一瞥

本课程对 C++20 只要求认得出特性、说得出用途。先看两个可运行的例子：

示例12：指定初始化器与三路比较

知识点：C++20 精选需要 -std=c++20
#include <iostream>

struct Point { int x; int y; };

int main() {
    Point p{.x = 1, .y = 2};      // C++20 指定初始化器：按成员名初始化
    std::cout << p.x << " " << p.y << "\n";

    int a = 3, b = 5;
    auto r = a <=> b;             // C++20 三路比较：一次给出 小于/等于/大于
    std::cout << (r < 0) << (r == 0) << (r > 0) << "\n";
    return 0;
}
▶ 预期输出
1 2
100

逐行解释

  • 第6行：{.x = 1, .y = 2} 按成员名字初始化，一眼看出哪个值给哪个成员（必须按声明顺序写，C 语言的乱序写法在 C++ 里不允许）。
  • 第10行：a <=> b 一次比较出三种关系（3 < 5，结果为“小于”类别的值）。
  • 第11行：r < 0 为 true 输出 1，r == 0、r > 0 为 false 输出 0 → 连起来是 100。它最大的用途：给自己的类自动生成全部六个比较运算符。

⚠ 易错点

指定初始化器必须按成员声明顺序：Point{.y = 2, .x = 1} 是编译错误。另外它是 C++20 特性，用 -std=c++17 编译示例 12 会报错。

concepts：给模板加约束——把“T 必须是整数”写成代码，违反约束时报错更简短：

// 片段（-std=c++20，需 #include <concepts>）
template <std::integral T>
T twice(T x) { return x * 2; }

twice(21);    // OK：21 是整数
twice(1.5);   // 编译错误：double 不满足 integral 约束

ranges：管道式数据处理——用 | 把“过滤、变换”串起来（惰性求值，不产生中间容器）：

// 片段（-std=c++20，需 #include <ranges>）
auto evens = std::vector{1, 2, 3, 4, 5, 6}
           | std::views::filter([](int x) { return x % 2 == 0; })
           | std::views::transform([](int x) { return x * 10; });
// 遍历 evens 依次得到 20 40 60
concepts、ranges 管道、三路比较 <=>、指定初始化器均为 C++20 新增；GCC 10 及以上对这四个特性支持较完整，编译需 -std=c++20。课程只作了解，不作考点重点。

11. 常见错误

1. 想用外部变量却忘写捕获列表：auto f = [] { return total; }; 报 'total' is not captured。修复：把 total 写进 []（按值或按引用）。
2. 按值捕获却想修改：[total]() { total += x; } 报 assignment of read-only variable。想改原变量用按引用 [&total]；只想改自己的副本加 mutable。两者效果完全不同，见示例 4。
3. 有捕获的 lambda 赋给函数指针：int (*fp)(int) = addBase; 报 cannot convert。有捕获的闭包携带状态，只有无捕获 lambda 能转函数指针；通用场合用 std::function（示例 9）。
4. 以为 [=] 能捕获一切：全局变量、静态存储期变量本来就直接可见，无需也不能捕获；成员函数里访问成员需要 [this]（C++20 起 [=] 隐式捕获 this 已弃用，要显式写）。
5. 用 sort / count_if 忘了头文件：报 'sort' is not a member of 'std'。修复：#include <algorithm>。
sort 比较器写成 >=（破坏严格弱序）：std::sort 要求比较器满足“严格弱序”——相等元素的 comp(a,b) 和 comp(b,a) 都必须是 false。写成 [](int a, int b) { return a >= b; } 后，相等的两个元素两个方向都返回 true，标准未规定会发生什么：libstdc++ 调试模式会直接 abort，普通模式可能越界访问内存。这是未定义行为，不是“排得慢一点”。修复：用 > 或 <。

更多同类错误见 编译错误博物馆（如 "is not captured"、“cannot convert”），考前再刷一遍 考试易错点。

本章小结

Lambda = 捕获列表 + 参数 + （返回类型） + 函数体：它让“一小段逻辑”第一次可以写在调用处。用它的关键只有两件事——捕获什么、捕获的变量能活多久。
  • 语法：[捕获](参数) -> 返回类型 { 函数体 }；返回类型通常省略，多 return 类型不一致时必须写。
  • 捕获四式：[x, &y] 逐个列、[=] 全按值、[&] 全按引用、[=, &total] 混合（默认符必须写最前）。按值捕获是定义时刻的快照。
  • 按值副本默认 const：mutable 只解除副本的 const，原变量不受影响；要改原变量请按引用。
  • 寿命规则：按引用捕获的 lambda 一旦逃出作用域就是悬空引用（UB）——逃逸场合按值捕获，或保证变量活得够久。
  • 可调用对象：无捕获 lambda 可隐式转函数指针；有捕获的装 std::function；STL 算法（sort/count_if/for_each）是 lambda 的主场。
  • 现代特性：C++14 泛型 lambda / 初始化捕获；C++17 结构化绑定 / if 带初始化 / optional / string_view / CTAD；C++20 concepts / ranges / <=> / 指定初始化器。
