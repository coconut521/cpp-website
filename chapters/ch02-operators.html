第2章 运算符与表达式

运算符（operator）规定运算方式；表达式（expression）是由运算符和操作数组成的、既有值又有类型的东西。

学习目标

  • 说清 i++ 与 ++i 各自返回什么值、何时加 1；识别 i = i++ + 1; 这类未定义行为并改写成安全写法。
  • 预测 7 / 2、-7 / 2、7 % 2、-7 % 2 的结果，知道除零在整数与浮点下的不同结局。
  • 解释 0.1 + 0.2 为什么“显示 0.3 却不等于 0.3”，写出 epsilon 误差比较。
  • 解释 -1 < 1u 为什么是 false，掌握整型提升与混合运算的转换链。
  • 记住最易错的优先级组合（<< 与 <、& 与 ==），拿不准时加括号。
  • 使用逗号、三目、赋值表达式的值。

前置知识：第1章 变量与基本类型。

1. 自增与自减：i++ 与 ++i

自增 ++ 让变量加 1，自减 -- 让变量减 1，各有两种写法：后缀 i++ 与前缀 ++i。两者的副作用相同（都让 i 加 1），差别在表达式本身的值：i++ 的值是旧值（先取值，后自增），++i 的值是新值（先自增，后取值）。

示例1：i++ 取旧值，++i 取新值

知识点：自增运算符高频考点
#include <iostream>

int main() {
    int i = 5;
    std::cout << i++ << "\n";   // 先取旧值 5 打印，再让 i 变 6
    std::cout << i   << "\n";   // 6

    int j = 5;
    std::cout << ++j << "\n";   // 先加 1 变 6，再打印新值
    std::cout << j   << "\n";   // 6
    return 0;
}
▶ 预期输出
5
6
6
6

逐行解释

  • 第5行：i++ 是后缀：整个表达式的值是 i 的旧值 5，打印 5；随后副作用发生，i 变成 6。
  • 第6行：i 已经是 6。
  • 第9行：++j 是前缀：先让 j 变成 6，表达式的值是新值 6，打印 6。
  • 第10行：j 保持 6。

变体对比

同理，i-- 取旧值后减 1，--i 先减 1 再取新值。判断题“i++ 与 ++i 对 i 的最终效果不同”——假，两者的副作用完全一样，不同的只是表达式取的值。

⚠ 易错点

std::cout << i++ 打印的是加 1 之前的值。

用下面的自增自减动画元件观察“取值”与“加 1”谁先谁后：

单独成句时两者等价；循环里推荐 ++i。如果 i++; 或 ++i; 独占一条语句、返回值没人用，两者效果完全相同。但要对类类型（如 STL 迭代器、大对象）多想一步：重载后的后缀 it++ 必须先构造一个“旧值副本”再自增，白白多一次拷贝；前缀 ++it 直接改自己，通常更高效。所以 STL 的惯用写法是 ++it。对 int 这类内建类型，现代编译器生成的机器码没有区别。

2. 一条语句只修改变量一次

自增自减和赋值都带副作用（会改变内存）。C++ 标准只保证：在同一个表达式里，对同一个变量的多次修改之间、以及“修改”与“读取”之间的先后顺序，只有在明确规定的场合才是确定的。顺序不明确时，就是未定义行为。

示例2：同一表达式里修改两次——UB 示范

未定义行为示范
#include <iostream>

int main() {
    int i = 1;
    i = i++ + 1;    // ⛔ 这一句里 i++ 改了一次 i，= 又改一次 i
    std::cout << i << "\n";
    return 0;
}

⚠ 为什么没有“预期输出”？

第5行对 i 做了两次修改（i++ 一次、赋值 = 一次），而这两次副作用之间没有顺序保证——标准明文规定这是未定义行为：结果可能是 2、可能是 3，开优化后还可能完全出乎意料。同理，v[i] = i++;（i 既当下标被读、又被 i++ 改）在 C++11/14 下同样是 UB；C++17 给赋值和下标补上了求值顺序之后，这一句才变得有定义，但换个组合（如 i = i++ + 1;）仍是 UB。正确的做法永远是：一条语句里每个变量最多修改一次，其余拆开写。g++ 用 -Wall -Wsequence-point 能对这类代码给出警告。

这类代码在考试中若出现“输出是多少”的选项，正确答案只能是“未定义行为”——但更常见的考法是让你认出并改正它。

逐行解释

  • 第5行：问题不在“看得懂看不懂”，而在标准不给答案。编译器不报错不等于没问题——UB 的定义就是“标准不管”。
  • 第6行：如果第 5 行已被替换成安全写法，这里才会输出确定的结果。

❌ 依赖未定义顺序的写法

i = i++ + 1;   // 改两次
v[i] = i++;    // 又读又改
a[i++] = i;    // 同上

✅ 一句一改，意图清晰

i = i + 1;     // 或 ++i;
v[i] = i;      // 先用后改
++i;
a[i] = i + 1;
C++98/03 对求值顺序的规定很松，i = i++ + 1; 一类的经典例句大量落入 UB；C++17 明确了 <<、>>、下标、赋值等运算符左右操作数的先后，救活了个别例句，但 i = i++ + 1; 至今仍是 UB。不要依赖标准版本，一句一改最安全。

3. 短路求值：&& 与 ||

&&（逻辑与）与 ||（逻辑或）不总把两边都算完：&& 的左边为假时右边不算（整体必假）；|| 的左边为真时右边不算（整体必真）。标准保证左操作数先于右操作数求值——所以右边被跳过时，它的副作用也一起被跳过。

示例3：右边被跳过时，自增也没发生

知识点：短路求值高频考点
#include <iostream>

int main() {
    int a = 0, b = 0;

    bool r1 = ++a > 0 || ++b > 0;   // 左为真：右边不计算
    std::cout << r1 << " " << a << " " << b << "\n";

    bool r2 = a < 0 && ++b > 0;     // 左为假：右边不计算
    std::cout << r2 << " " << a << " " << b << "\n";

    bool r3 = a > 0 && ++b > 0;     // 左为真：右边才算
    std::cout << r3 << " " << a << " " << b << "\n";
    return 0;
}
▶ 预期输出
1 1 0
0 1 0
1 1 1

逐行解释

  • 第6~7行：++a 让 a 变 1，1 > 0 为真；|| 短路，右边 ++b 根本没有执行，b 保持 0。输出 1 1 0（bool 默认打印 1/0）。
  • 第9~10行：a < 0 为假；&& 短路，++b 没有执行，b 仍是 0。输出 0 1 0。
  • 第12~13行：a > 0 为真，这次右边才被计算：++b 让 b 变 1。输出 1 1 1。

变体对比

把第 9 行的 && 换成 &（按位与）就不短路了：两边都会算，b 会变成 1。

⚠ 易错点

别把有副作用的操作藏在条件右边然后指望它执行：if (x != 0 && ++count > 0)——x 为 0 时 count 不一定自增。需要“无论如何都计数”就把它写到条件外面。

短路常用作守卫：if (n != 0 && total / n > 60)——n 为 0 时右边根本不执行，避免整数除零的 UB（见第 5 节）。同理 if (p != nullptr && ...) 是指针判空的惯用写法（指针详见后续章节）。

4. 运算符优先级与结合性：最易错的四组

优先级决定“先算谁”，结合性决定同级运算“从左还是从右算起”。不必背整张表，先记住最常考的四组：

写法实际含义想要的写法
cout << 1 < 2(cout << 1) < 2——<< 优先级高于 <，先流插入再比较，编译错误cout << (1 < 2)
x & 1 == 0x & (1 == 0)——== 高于 &，先判等再按位与(x & 1) == 0
-i++-(i++)——后缀 ++ 高于一元负号：先取旧值再自增，最后取负拆成两句，如 --i; 或 int t = -i; ++i;
a = b = 5a = (b = 5)——赋值右结合，先把 5 给 b，再把表达式的值 5 给 a确认链式赋值是有意为之

示例4：x & 1 == 0 与 (x & 1) == 0 差在哪

知识点：优先级高频考点
#include <iostream>

int main() {
    int x = 4;

    std::cout << ((x & 1) == 0) << "\n";  // 1：先按位与，再判等
    std::cout << (x & 1 == 0) << "\n";    // 0：== 优先级更高
    return 0;
}
▶ 预期输出
1
0

逐行解释

  • 第6行：(4 & 1) 得 0（二进制 100 & 001），0 == 0 为真，输出 1。这是“判断 x 是不是偶数”的正确写法。
  • 第7行：不加括号时 == 先算：1 == 0 得 false（转成 0），再算 4 & 0 得 0，输出 0——结果直接反过来。

变体对比

一元负号与后缀 ++ 的组合：-i++ 是 -(i++)——先取 i 的旧值取负，再让 i 自增。设 int i = 3;，std::cout << -i++; 输出 -3，随后 i 为 4。想表达“先取负再减 1”请直接写 --i 配合取负，或拆成两条语句。

⚠ 易错点

cout << 1 < 2 不是“输出比较结果”，而是编译错误：它被读成 (cout << 1) < 2，流对象没法和整数比较。比较表达式放进 << 链时必须自带括号。

完整的优先级总表（约 18 级）放在速查表专区，考前过一遍即可：见 速查表：运算符优先级与结合性。日常守则只有一条——拿不准就加括号。

5. 整数除法与取余

第 1 章埋的伏笔现在揭晓：7 / 2 两侧都是 int 时发生的是整数除法，小数部分直接丢弃（向零截断）。% 是取余（取模）运算符，只对整数有意义，并满足恒等式 (a / b) * b + a % b == a。

示例5：负数参与整数除法与取余

知识点：/ 与 %高频考点
#include <iostream>

int main() {
    std::cout << 7 / 2 << "\n";    // 3：整数除法，向零截断
    std::cout << -7 / 2 << "\n";   // -3：不是 -4！
    std::cout << 7 % 2 << "\n";    // 1
    std::cout << -7 % 2 << "\n";   // -1：余数符号跟被除数
    std::cout << 7.0 / 2 << "\n";  // 3.5：有浮点参与才是浮点除法
    return 0;
}
▶ 预期输出
3
-3
1
-1
3.5

逐行解释

  • 第4行：7 / 2 商 3 余 1，整数除法丢掉小数 → 3。
  • 第5行：C++11 起规定整数除法向零截断：-3.5 截成 -3（不是向 -∞ 方向的 -4）。
  • 第6行：7 % 2 = 7 - 3×2 = 1。
  • 第7行：由恒等式，-7 % 2 = -7 - (-3)×2 = -1。余数的符号与被除数相同。
  • 第8行：7.0 是 double，2 被提升为 2.0，做的是浮点除法 → 3.5。想要小数，让除法里出现至少一个浮点数。

变体对比

7 % -2 呢？商向零取整是 -3，余数 = 7 - (-3)×(-2) = 1——符号依然跟被除数 7。无论除数正负，余数符号只看被除数。

⚠ 易错点

“-7 / 2 等于 -4”是常见错误（那是向 -∞ 取整，Python // 的行为）。C++11 起一律向零截断得 -3。

整数除零是未定义行为：7 / 0、7 % 0 都没有定义——程序可能崩溃（Windows 上常表现为浮点异常）、可能输出垃圾值、可能被编译器优化改变行为。另外 INT_MIN / -1（最小 int 除以 -1，结果超出 int 范围）也是 UB。写除法前先确认除数不为 0，或用短路求值做守卫（第 3 节）。浮点除零不是这条路：见第 6 节，主流平台上它给出 inf。
C++98/03 时代，含负操作数的整数除法允许实现选择“向 -∞ 取整”（-7 / 2 可能得 -4）；C++11 起统一规定向零截断，% 的符号随之固定为“与被除数相同”。

6. 浮点数：精度、比较与 inf

double 用二进制存数，很多十进制小数（如 0.1）在二进制里是无限循环小数，只能近似存储。于是 0.1 + 0.2 的真实结果是 0.30000000000000004……而 cout 默认只输出 6 位有效数字，恰好把它显示成 0.3——显示像相等，存储不相等。

示例6：0.1 + 0.2 显示 0.3，却不等于 0.3

知识点：浮点精度高频考点
#include <iostream>
#include <cmath>

int main() {
    double a = 0.1 + 0.2;
    std::cout << a << "\n";                            // 0.3：默认 6 位有效数字
    std::cout << (a == 0.3) << "\n";                   // 0：并不相等！
    std::cout << (std::fabs(a - 0.3) < 1e-9) << "\n";  // 1：误差在允许范围内
    std::cout << 1.0 / 3.0 << "\n";                    // 0.333333
    std::cout << std::isinf(1.0 / 0.0) << "\n";        // 1：浮点除零得 inf
    return 0;
}
▶ 预期输出
0.3
0
1
0.333333
1

逐行解释

  • 第6行：a 的真实值约 0.30000000000000004，cout 按 6 位有效数字显示为 0.3。
  • 第7行：== 是精确比较。a 的二进制表示与字面量 0.3 的二进制表示不同 → false，打印 0。
  • 第8行：正确姿势：判断两者之差的绝对值是否小于一个很小的 epsilon（这里取 1e-9）→ true，打印 1。
  • 第9行：1/3 是无限循环小数，double 存的是近似值；6 位有效数字显示为 0.333333（六个 3，不是 0.33 也不是 1/3）。
  • 第10行：浮点除以 0 在支持 IEEE 754 的主流平台上得到 ±inf（无穷大），程序不崩溃；std::isinf 返回 1 表示“是无穷大”。若直接 std::cout << (1.0 / 0.0)，主流实现打印 inf。

变体对比

想要看更多位？std::cout << std::setprecision(17) << a;（需 <iomanip>）会显示 0.30000000000000004。速查表里有完整的格式化输出对照。

⚠ 易错点

“cout << 0.1 + 0.2 输出 0.30000000000000004”——错，默认精度下输出 0.3；显示 0.3 不等于存储值是 0.3。

浮点比较三步：① 算差的绝对值 std::fabs(x - y)；② 与合适的 epsilon 比（数量级依问题而定）；③ 不用 ==。fabs、isinf 等函数都在 <cmath> 里。

7. 类型转换与整型提升

两种类型混在一起运算时，编译器会把其中一方隐式转换成另一方，转换总朝“表达能力更强”的方向进行：

混合运算转换方向例子
char / short 参与算术整型提升为 int'A' + 1 → 66
int 与 unsignedint → unsigned-1 < 1u → false（本节示例）
整数与浮点整数 → 浮点7 / 2.0 → 3.5
float 与 doublefloat → double3.14f + 1 → double

第二条最危险：有符号与无符号混用时，有符号一方转成无符号。负数转无符号按模回绕，-1 变成最大值。

示例7：-1 < 1u 是 false

知识点：有符号/无符号混用高频考点
#include <iostream>

int main() {
    int i = -1;
    unsigned u = 1;
    std::cout << (i < u) << "\n";   // 0！-1 被转成 4294967295 再比
    std::cout << (i + u) << "\n";   // 0：4294967295 + 1 回绕为 0
    std::cout << (i < 1) << "\n";   // 1：双方都是有符号，比较正常
    return 0;
}
▶ 预期输出
0
0
1

逐行解释

  • 第6行：int 与 unsigned 比较，i 先被转换成 unsigned：-1 按模 232 回绕为 4294967295。4294967295 < 1 为假 → 0。这是定义好的行为，不是 UB。
  • 第7行：同理，i + u 按无符号算：4294967295 + 1 回绕为 0（无符号回绕是定义好的，见第 1 章示例 4）。
  • 第8行：两侧都是有符号 int，正常比较，-1 < 1 为真 → 1。

变体对比

long（32 位平台上）与 unsigned int 混用则相反：unsigned int 会被提升为 long，负数不会回绕。规则：双方先整型提升，再向等级更高的一方转换；有符号与无符号同级时，有符号让位。与其背转换表，不如让类型保持一致。

⚠ 易错点

sizeof(v) < n 这类比较（sizeof 返回无符号类型）在 n 为负或有符号时同样会中招。防御方法：开启 -Wall -Wsign-compare，让编译器替你盯住。

int 与 unsigned 比较时，int 会被转成 unsigned——-1 变成约 43 亿，< 变假。课程代码里能不用 unsigned 就不用；必须用（如 size()）时，别拿它和可能为负的 int 比较。

8. 逗号、三目与赋值表达式

C++ 里赋值不是语句而是表达式，它有值（被赋的那个值）；三目运算符 条件 ? 值1 : 值2 是唯一的三元运算符，两个分支之一就是整个表达式的值；逗号运算符 a, b 先算 a 丢掉结果，取 b 的值——它优先级最低。

示例8：三目取大、逗号取末值、赋值右结合

知识点：表达式求值
#include <iostream>

int main() {
    int a = 3, b = 7;
    int bigger = (a > b) ? a : b;        // 三目：条件为真取 a，否则取 b
    std::cout << "较大值: " << bigger << "\n";

    int x = 0;
    int t = (x = 2, x * 5);              // 逗号：先算 x=2 丢弃，再算 x*5
    std::cout << "逗号: " << t << ", x=" << x << "\n";

    int p, q, r;
    p = q = r = 1;                       // 右结合：r=1 → q=1 → p=1
    std::cout << p << q << r << "\n";
    return 0;
}
▶ 预期输出
较大值: 7
逗号: 10, x=2
111

逐行解释

  • 第5行：3 > 7 为假，取冒号后的 b → 7。三目常用于“二选一”赋值。
  • 第9行：逗号运算符取最后一个子表达式的值：先执行 x = 2（副作用保留），再算 x * 5 = 10 → t = 10。整个式子必须加括号，否则 = 的优先级会抢先生效。
  • 第13行：赋值右结合，等价于 p = (q = (r = 1))，三个变量都是 1，连起来打印 111。

变体对比

三目两个分支的类型不同时会向公共类型转换：(x > 0) ? x : 0.5 的结果是 double——即使走了 int 分支，值也被转成浮点。赋值表达式的值则一定是被赋的类型：if ((n = count) != 0) 是“赋值并判断”的惯用法（注意是两个等号里只想要一个的场景，别与 == 混淆）。

⚠ 易错点

不是所有逗号都是逗号运算符：变量定义 int a = 1, b = 2; 和函数参数 f(a, b) 里的逗号只是分隔符，不参与“取最后一个值”。考题常拿 int t = x = 2, x * 5; 设陷阱——它根本编译不过（逗号被当成定义分隔符）。

9. 综合示例：平均分的两种算法

示例9：sum / 3 与 sum / 3.0

综合
#include <iostream>

int main() {
    int s1 = 92, s2 = 88, s3 = 79;
    int sum = s1 + s2 + s3;
    int avgInt = sum / 3;          // 整数除法：86，小数被丢掉
    double avgReal = sum / 3.0;    // 有 double 参与：真正的除法

    std::cout << "总分: " << sum << "\n";
    std::cout << "整数平均: " << avgInt << "\n";
    std::cout << "实数平均: " << avgReal << "\n";
    return 0;
}
▶ 预期输出
总分: 259
整数平均: 86
实数平均: 86.3333

逐行解释

  • 第5行：92 + 88 + 79 = 259。
  • 第6行：259 / 3 两侧都是 int → 整数除法得 86，余 1 被丢弃。
  • 第7行：3.0 是 double，259 被提升为 259.0 → 86.333333…，存入 double。
  • 第11行：cout 默认 6 位有效数字：86.333333… 显示为 86.3333（6 位有效数字，恰好 4 位小数）。

变体对比

把第 7 行写成 double avgReal = (double)sum / 3; 也行——先转换 sum，除法就是浮点的。但 (double)(sum / 3) 不行：先整数除法已经丢了余数。转换的时机在除法之前还是之后，结果不同。

⚠ 易错点

double avg = (a + b) / 2;（a、b 是 int）平均分照样丢小数。让除数或被除数带一个 .0，是最省事的修复。

11. 常见错误

1. 想要小数却写整数除法：7 / 2 得 3。修复：任一侧写成浮点 7.0 / 2，或先转换再除（转换时机要在除法之前）。
2. 有符号与无符号混用：-1 < 1u 是 false。修复：类型保持一致；必须混用时开 -Wall -Wsign-compare。
3. 浮点用 == 判等：(0.1 + 0.2) == 0.3 为 false。修复：std::fabs(x - y) < eps。
4. 位运算忘加括号：x & 1 == 0 实为 x & (1 == 0)。涉及 &、|、<< 与比较运算混写时，一律加括号。
5. 以为 -7 % 2 是 1：那是数学/Python 的习惯。C++11 起整数除法向零截断，余数符号同被除数，-7 % 2 = -1。
6. 同一表达式里多次修改同一变量：i = i++ + 1;、v[i] = i++;（C++11/14）等都是未定义行为，没有“正确输出”可言。修复：一条语句只修改一次。

12. C++ 标准差异小结

特性C++98/03C++11 及以后
负操作数的整数除法实现定义（可向 -∞ 取整）统一向零截断：-7 / 2 = -3
% 的符号随除法取整方式而变固定为与被除数相同：-7 % 2 = -1
std::isinf / std::isnan非标准（编译器扩展）<cmath> 标准提供
复杂表达式求值顺序大量未指明（经典 UB 例句的温床）C++17 明确 <<、>>、下标、赋值等的顺序；i = i++ + 1 仍是 UB
判断题“-7 / 2 在任何 C++ 标准下都是 -3”——假：C++98/03 允许实现得 -4，C++11 起才统一为 -3。考试默认按现行标准（C++11 及以后）作答。

本章小结

每个运算符都要回答两个问题：“算出什么值”与“留下什么副作用”。i++ 取旧值、&& 与 || 会短路、赋值/三目/逗号都有值——而同一表达式改两次同一变量时，标准不定义结果。
  • i++ 取旧值后加 1，++i 先加 1 取新值；单独成句时等价，循环里推荐 ++i。
  • i = i++ + 1; 这类“一式多改”是 UB，一句一改。
  • && 左假右不算，|| 左真右不算——右边的副作用也被跳过；这是标准的守卫机制。
  • 整数除法向零截断（-7/2 = -3），余数符号同被除数（-7%2 = -1）；整数除零是 UB，浮点除零（IEEE 754 平台）得 inf。
  • cout 默认 6 位有效数字：0.1 + 0.2 显示 0.3 却不等于 0.3，浮点判等用 epsilon。
  • 有符号与无符号混用时，有符号一方转成无符号：-1 < 1u 为 false。
  • 优先级最易错四组：<< 高于 <、== 高于 &、后缀 ++ 高于一元负号、赋值右结合——拿不准就加括号。
